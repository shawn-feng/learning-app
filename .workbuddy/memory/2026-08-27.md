## Mac 语音输入失效修复（ffmpeg-static 架构不匹配）

- 现象：Mac 上语音输入报"在 application 的 node_modules 找不到 ffmpeg-static"（实为 ffmpeg 执行失败的类比表述）。用户为 **Intel Mac（macOS 12.7.6）+ x64 dmg**。
- 根因（已验证，非猜测）：`ffmpeg-static` 是带原生二进制的 npm 包，二进制不在 `files` 字段、由 `install.js` 在 `npm install` 时下载。GitHub `macos-latest` 是 **arm64** 机器，`npm ci` 默认下载 **arm64** ffmpeg。x64 dmg 里若塞 arm64 二进制，Intel 芯片无法执行 → 语音输入挂。
  - CI 的 `file` 验证实锤：初版 x64 job 的 ffmpeg 竟是 `Mach-O 64-bit executable arm64`（错误）。
- 修复（已落地并验证通过，run `33026159079` success）：
  1. `build-mac.yml` 改为 matrix `[x64, arm64]`，每个 job 先 `rm -f node_modules/ffmpeg-static/ffmpeg` 再 `npm_config_arch=<arch> npm rebuild ffmpeg-static`。**必须删旧二进制**——`install.js` 第39行见文件已存在会 `process.exit(0)` 跳过下载，否则 arch 环境变量完全不生效（首版就栽在这）。
  2. `package.json` 加 `"asar": true` + `"asarUnpack": ["**/node_modules/ffmpeg-static/**"]`（二进制必须解包到 asar 外才能 exec）。
  3. `electron/lib/voice/audio.ts`：顶层 `import ffmpegStatic` 改为 `getFfmpegStaticPath()` 懒 require + try/catch 容错，模块缺失/不可用时不再拖垮整个语音功能，报错清晰。
- 验证结果：`file` 输出 x64 job = `Mach-O 64-bit executable x86_64`（78MB）、arm64 job = `arm64`（45MB），两 job 均 success。
- 产物：Actions Artifacts 现分 `macos-dmg-x64`、`macos-dmg-arm64`（之前单次构建叫 `macos-dmg`，已废）。用户用 `macos-dmg-x64`。
- 提交链：ae3d611（asarUnpack+容错+matrix初版）→ dded5c0（rm+rebuild 修正）→ 2571cae（PACKAGING.md 记录）。
- 教训：electron 项目用 `ffmpeg-static` 做双架构 Mac 包时，**不能靠单次 `npm ci` + 单 dmg**，必须按目标架构分别安装/构建，且 `install.js` 的「已存在即跳过」是隐形坑。

## Mac 最大化不能占满屏幕修复
- 现象：Mac 上点最大化后不能像系统其它 App 那样占满屏（无边框 `frame:false` 窗口）。
- 根因：`electron/lib/ipc-handlers.ts` 的 `window:maximize-toggle` 直接调 `w.maximize()/w.unmaximize()`；macOS 无边框窗口的「缩放」不会占满整个工作区，且自定义标题栏无原生缩放承载。
- 修复（已落地并验证，run `33027907578` success，commit `f05ddcb`）：macOS 分支改为 `screen.getDisplayMatching(w.getBounds()).workArea` 精确 setBounds 填满（=系统原生「缩放」行为，顶部留菜单栏，与其余 App 一致）；用模块级 `macMaximizedPrevBounds` 记录还原前 bounds，`window:is-maximized` 同步返回该状态。Windows/Linux 保持原生 `maximize()`。
- 用户需重装 `macos-dmg-x64`（run 33027907578）验证。
