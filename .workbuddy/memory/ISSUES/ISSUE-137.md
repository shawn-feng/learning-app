# ISSUE-137 · 「针对错题创建一次考核」（F5）怎么处理 —— 方案与取舍

- **类型**：需求 / 设计（含一处接口粒度限制，待拍板；**本轮只出方案，不改代码**）
- **描述**：孩子端 F 域新增一个使用场景——**针对错题创建一次考核**（孩子说"我错的那几道题再考我一次"）。但现状有两条硬约束：**① 创建考核必须挂课程**，而**错题不一定关联课程**；**② 考核只能指定到知识点**，**无法指定到具体某道题**。本文把这两条卡点核实到字段级，给出三条可选路线与建议。
- **影响范围**：**取决于路线**——B/C 是"提示词 + 工具返回字段"级别；A 是**协议级**（改 `exam_plans.scope_json` 契约 + 出题装配 + 校验），并牵连家长端考核面板与列表展示。
- **排查/修改入口**：
  - 考核创建（工具）：`server/src/agent/plan-tools.ts:487` `createChildExamPlanCreateTool`
  - 考核创建（REST）：`server/src/routes/exam.ts:1001` `POST /api/v1/exam/schedules`
  - 出题约定与抽题：`server/src/assess-selection.ts`（`buildPlanSpecEntries` / `attachPlanQuestions` / `parsePlanCourses` / `PlanKpSpec`）
  - 错题本读写：`server/src/db/mistakes.ts`、孩子工具 `server/src/agent/child-db-tools.ts:196` `child_mistake_log`、考核错题同步 `server/src/routes/exam.ts:1347`
  - 可读登记：`server/src/agent/db-channel.ts:1185`（`mistake_book` 已在孩子可读表清单里）
- **优先级**：中（不是阻塞项；错题本的复习闭环可先顶上）
- **记录时间**：2026-09-23
- **关联**：`docs/孩子使用场景梳理-2026-09-23.md`「域 F 讨论 · 补」/ §6 硬约束 #10 #11 / §8 待确认 #12；`ISSUE-114`（错题本与复习闭环，本场景的上游）；`ISSUE-136`（F5 的提示词段落依赖本方案）；`ISSUE-135`（考核结果与知识点流水的关联方式）；`ISSUE-121`（考核命名与同日多场）。

## 一、场景

| 项 | 内容 |
|---|---|
| **孩子会说** | 「我错的那几道题再考我一次」「把错的给我出个考核」「上次错的字词考考我」 |
| **期望结果** | 得到一次**围绕自己错题**的检验，验证是否真的会了 |
| **形态** | 对话（F 域） |
| **涉及工具** | `child_mistake_log`（取错题）→ `child_exam_plan_create`（建考核） |

## 二、先把"错题"分三类（决定能不能做）

`mistake_book` 单表、按 `kind` 分类，**不同来源写入的字段完整度差别很大**——这是本场景的关键：

| 来源 | 谁写的 | `course_ref` | `question_id` | 知识点 | 能不能进考核 |
|---|---|---|---|---|---|
| **考核错题**（交卷自动同步） | `routes/exam.ts:1347`，`source=exam` | ✅ 有（考核时的课名） | ✅ 有（题库题目 uuid） | ✅ 有（`kpId`，为空时 content 里写"题目"） | **可以**（现状只能知识点级） |
| **对话口述错题** | `child_mistake_log(action=log)`，`source=conversation` | ⚠ 可选（`course` 参数给了才有） | ❌ 无 | ❌ 无 | **不行**（连课程都可能没有） |
| **生字 / 薄弱点** | 同上 / 查词浮层 | ⚠ | ❌ | ⚠ | **不该考**（生字不是题） |

## 三、三个卡点（核实到代码）

| # | 卡点 | 实测证据 |
|---|---|---|
| 1 | **课程是必填的顶层维度** | `exam_plans.scope_json.courses = [{title, kps:[{name,count}]}]`；创建时（`plan-tools.ts:582` 与 `routes/exam.ts:1040` 同口径）先按**课名**落孩子库 `courses` → 家长库 uuid → 知识点（`buildPlanSpecEntries`）。**没有课程直接建不出来**（工具会报"这些课程在孩子库里确认不到"） |
| 2 | **最细只到"知识点 + 题数"** | scope 的 `kps` 结构只有 `{name, count}`（`PlanKpSpec`）；出题 `attachPlanQuestions` 按知识点取 `pool`、**洗牌随机抽前 N 道**——**没有题目维度**，无法锁定某道题 |
| 3 | **口述错题连知识点都没有** | `child_mistake_log` 的入参只有 `action / kind / content / detail / course / id / status`——**没有知识点、没有题目**；写库只落 `course_ref` |

**附带发现两条（都是实现细节级、但会直接卡住路线 B）**：

- **`child_mistake_log(action=list)` 的返回里不含 `course_ref` / `knowledge_point_name` / `question_id`**（`child-db-tools.ts:262-268` 只打印 id/kind/content/count/detail 前 80 字）⇒ **即使错题带着课程与知识点，模型从 list 里也看不到**，没法据此建考核。绕法：改用 **`child_db_read` 读 `mistake_book`**（该表**已在孩子可读清单**里，`db-channel.ts:1185`，有 `question_id` / `course_ref` / `knowledge_point_id`）。
- **`course` 参数的描述是"关联主题/课程名（如 论语）"——主题名与课程名混用**，而 `course_ref` 是**文本快照**、去重键是 `(content, kind, course_ref)`。若孩子说"论语"（主题名）被写进 `course_ref`，**按课名反查课程会失败**。⇒ 该参数要么收窄为"课程名"，要么在 F5 里明确"只认课名快照"。

## 四、关键洞察：**"必须挂课程"不是死结**

只要错题带了 **`question_id`**，课程与知识点就**都能反查出来**——题目活在题库里，天然属于某课程的知识点（`question_bank` / `knowledge_points` / `course_knowledge_questions`）。所以真正的问题不是"错题有没有课程"，而是"**错题有没有 `question_id`**"：

| 错题带的东西 | 能定位到 | 缺的只是 |
|---|---|---|
| **`question_id`** | 原题 + 知识点 + 课程（**三样全有**） | "锁原题"这个能力（卡点 2） |
| **只有知识点名快照** | 知识点（课程要靠课名匹配，改名/重建会断） | 课程可能对不上 |
| **什么都没有（口述）** | — | 建不了，**也不该硬建** |

## 五、三条可选路线

| 路线 | 做法 | 能考到原题吗 | 代价 | 建议 |
|---|---|---|---|---|
| **A 题级锁定** | scope 增加题目维度：`courses[].questions: [question_id]`（与 `kps` 互斥或叠加）→ 出题时**按 id 直取、跳过随机池**；`buildPlanSpecEntries` 校验"该题存在且属于本课知识点"，否则拒绝创建 | ✅ **就是那道错题** | 改 `scope` 契约 + `attachPlanQuestions` 出题分支 + 创建侧校验 + `parsePlanCourses` 兼容旧格式 + 列表/面板展示（`formatPlanCourses`）+ 端到端测试；还要处理"题目被家长删改" | **二期** |
| **B 知识点级**（现状可做） | 用现有 `methodSpec.require = {「错题所在知识点」: N}` 建考核（或退一步：只按课程建，考该课全部知识点） | ❌ 抽到的是**同知识点的随机题** | **数据层零改造**；但只要补两处**返回/口径**：① `child_mistake_log(list)` 补吐 `course_ref`/`knowledge_point_name`（或提示词改走 `child_db_read`）② **话术要诚实**（"同类题再练"，不承诺原题） | **推荐先行** |
| **C 不进考核** | 错题重做走**错题本自己的复习闭环**（`ISSUE-114` 已设计：讲解 → 重做 → 验证后标"会了"） | ✅ 可对着原题讲/重做 | 无场次、无分数、无成绩报告——语义是**复习**不是考试 | **推荐作为主路径** |

## 六、建议（C 为主、B 先行、A 留二期）

1. **"错题"的主导权应留在错题本，不在考核**：错题本已有"记下 → 复习 → 验证后标 mastered/ dismiss"的闭环设计（路线 C），而考核是**重流程**（场次/计分/成绩报告/加分项判定/结果落库三张表），**为几道错题拉一场考核并不划算**。
2. **孩子明确要"考我一次"时，先落 B**：零改造、当场可用；**AI 的话术必须诚实**——"我把你错的那几个点再考一遍"，**不要说"考原来那道题"**（抽题是随机的）。
3. **A 留作二期**：真要做"错题原题重考"，必须给 scope 加题目维度——属**协议级改动**，要一并定：`kps` 与 `questions` 是否互斥、题目被删改时的降级（报错拒绝 vs 自动回退知识点级）、家长端列表怎么展示"指定题目"。
4. **口述错题（无课程）不建考核**：交给 F1（共情 + 讲解 + 悄悄记录），把"重考"引导为**"我现在把这几道给你讲一遍 / 出两道同类题"**（当场口述练习，不落库）。
5. **要落地 B 的话，最少要做三件事**：① `child_mistake_log(list)` 补吐关联字段（或提示词明确改走 `child_db_read` 读 `mistake_book`）；② `child_exam_plan_create` 的课名解析支持"从错题反查课名"这条提示词路径；③ 写清"同类题、非原题"的口径（`ISSUE-136` [域 F] · F5）。

## 七、待拍板

1. **F5 走哪条路线**：**B 知识点级**（最小可用，先落地）/ **A 题级锁定**（二期，改协议）/ **只走错题本复习闭环**（不进考核）；可否"B + C 并行"（能定位的建考核、定位不到的走复习）？
2. **`child_mistake_log` 要不要加"知识点关联"参数**（现在只有 `course`，**没有知识点**）——不加的话，**口述错题永远进不了任何闭环**（既不能进考核，也无法按知识点复习）。
3. **`course` 参数的口径**：收窄为"**课程名**"（与 `course_ref` 的用途一致），还是维持"主题/课程名"混用（那 F5 就只能靠知识点快照匹配）？
4. **A 路线的降级策略**（若做）：错题指向的题目**已被家长删除/改写**时——拒绝创建（提示"这道题已经不在题库里了"）还是自动回退知识点级？

## 八、验收（做哪条验哪条）

- **B**：对一个"有知识点关联的考核错题"，说"把错的再考我一次"→ 能建出**限定到该知识点**的考核；对"无课程的口述错题"→ **不建考核**，改为当堂讲解（且**不谎称考原题**）。
- **C**：错题能在对话里被复习、验证后能标"会了"，且**不产生考核场次**。
- **A**：scope 里能存 `questions`，出题**确实出到指定那道题**；旧 scope（无 questions）行为不变；题目已被删时按 §七-4 的策略给出可读错误。
