- 用户反馈：家长设置里「编程 agent 模型」已选好并显示已保存，但家长 agent 调 parent_build_material 时报「编程 agent 未配置模型」。
- 报错唯一起源：`server/src/agent/programming-agent.ts` `getProgrammingSession` 读 `readParentSettings(...).appSettings?.["programmingModel"]` 为空即抛错（构建产物 `server/dist/server.cjs:375516` 同逻辑）。
- 排查结论：当前源码里「设置写入（pi:set_programming_model→POST /models/app_settings）」「设置显示（pi:get_programming_model→GET /models/settings）」「agent 读取（readParentSettings）」三条路径都收口到同一个服务端键 `${parentId}:app_settings`，且 parentId 同源（同一次 verifySession 的 parent_id）→ **正确构建下不可能出现本 bug**。
- 根因假设（最可能）：线上跑的是旧客户端构建，仍走 `electron/lib/app-settings.ts` 的本地 `app-settings.json` 分支——显示读本地→"已配置"，agent 读服务端 DB→空→"未配置"，典型本地/服务端存储分裂。次可能因 pushConfig 静默失败导致服务端缺字段。
- 落地前需核对：① 服务端 DB 里 `${parentId}:app_settings` 是否真有 `programmingModel` 字段；② 线上客户端 `pi:set/get_programming_model` 究竟引 `server-agent-client` 还是 `electron/lib/app-settings.ts`；③ 重新构建部署两端消除分裂。
- 详情见 `ISSUES/ISSUE-097.md`，索引计数更新为 97（标记🟡待处理）。
