## 语音朗读（TTS）实现完成（2026-08-14）

### 方案结论
- **Edge TTS 不依赖 Edge 浏览器**：它是微软独立在线服务（`speech.platform.bing.com`，TrustedClientToken 6A5AA1D4...），Edge 浏览器只是客户端。wowenglish 能"用 Edge 语音"是因为 HTML 在 Edge 里 `speechSynthesis` 内部调了这个服务；Electron 的 `speechSynthesis` 用系统语音（音质差），故不能照搬。
- 用户已有的 `Documents/AI work space/edge_tts` 空间用的是社区 Python 包 `edge-tts`（rany2），本身是"去 Edge 浏览器化"改造（原 LuckyHookin 项目靠内嵌 Edge WebView + 全局录音）。
- Electron 采用 Node 社区包 **`@andresaya/edge-tts`@1.8.0**（CJS，`new EdgeTTS()` → `synthesize(text, voice, {rate,volume,outputFormat})` → `toBuffer()` 返回 MP3）。

## TTS 内存 LRU 缓存（2026-08-14）
- 背景：TTS 原先每次点朗读都重新请求 Edge TTS 在线服务生成 MP3（`new EdgeTTS()` + `synthesize()`，无缓存），重复朗读浪费请求、有秒级延迟、可能触发限流。
- 改动：`electron/lib/voice/tts.ts` 加 `Map<string, Buffer>` 内存 LRU 缓存，上限 100 条。
  - key = `sha256(voice\u0000rate\u0000volume\u0000text)`，三者缺一不可（不同音色/语速产出不同音频）。
  - 命中：`delete` + `set` 移到队尾（LRU），直接返回 Buffer。
  - 未命中：联网合成 → 写入缓存 → 超上限 `cache.keys().next().value` 淘汰最旧。

## 凭证安全加固：云端二次校验（2026-08-14）

用户发现可通过改本地 `license.json` 的 `expires_at` 绕过登录。加固两处，把授权判断下沉云端：

### 改动
- `auth-manager.ts`：
  - 新增 `verifyLicenseWithCloud(token)` → 调 `POST /api/license/verify`（带 Bearer token），返回 `{valid, max_children}`；401/非 2xx 视为无效；网络错误返回 `null`（无法判断，降级）。
  - `checkAuth()` 从同步改**异步**：本地判断 `expires_at` 未过期后，**再向云端 verify 确认一次**——云端明确判定过期/失效则 `clearCachedLicense` 强制登出；云端连不上（null）则离线降级信任本地。
- `ipc-handlers.ts`：
  - `child:add` 的孩子上限改用云端 `verifyLicenseWithCloud` 返回的 `max_children`（本地缓存值仅作云端不可用时的回退），堵住"改 max_children 多建孩子"。
- `test/app.test.ts`：`checkAuth()` 改异步后，测试补 `await`。

### 安全边界结论
- 本地 `license.json` 只是「记住登录态」的便利层，不是安全边界。
- 真正权威在云端：token 是 JWT（HMAC 签名，72h），订阅 `expires_at` 存云端 SQLite。改本地文件只能骗过"跳过登录页"，骗不过任何需 token 的接口（sync、进家长中心 authVerify）。
- 离线降级：云端连不上时信任本地判断放行（孩子学习核心功能本就不依赖 license；断网时 sync 也用不了，风险有限）。

**验证**：构建 ✅、测试 ✅ 29/29 通过。
