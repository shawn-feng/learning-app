## 主题导入两阶段：同名冲突提示 + 允许改名（用户需求，2026-09-27 上午；服务端 0.5.17 已部署 201）

**需求**：「导入同名主题时，要提示一下，并允许修改主题名」。此前 apply 一步落库，同名不同 key 静默自动重命名、同名同 key 静默刷新——家长不知情、无改名机会。

**方案：导入拆两阶段**（`POST /import-topic` 加 multipart 字段）：
- `mode=inspect`：整包上传但**不写任何数据**，返回 `{name, topicKey, counts, conflict:{type: none|refresh|rename, suggestedName, suggestedKey}}`（zip 目录在包尾须收全才能解，大包双传的流式优化留待有痛点）；
- `mode=apply`（缺省，兼容旧客户端）：可带 `target_name`/`target_key`——家长在冲突提示里确认/修改后的身份；缺省走原自动策略。
- 客户端流（`TopicImportDialog` 重写）：选文件 → inspect → `none` 直接 apply；`refresh`/`rename` 显示黄色提示 + **可编辑的主题名/目录名**（预填建议值，如「论语 (2)」/`lunyu-2`）→ 确认导入 → 报告。改名换目录 = 资料落新目录、指针前缀同步改写。

**`resolveTargetIdentity` 的两条防覆盖铁律**（topics 主键是 name、courses 按 topic_key 归属，REPLACE 双向碰撞都会静默覆盖别人数据）：①目录名已被别的主题用 → 400「已被主题『X』使用」；②主题名已被别的目录用 → 400「已存在（目录 Y）」；③目录下有孤儿课程数据 → 400。`renamed` 语义 = 相对包内目录发生了前缀改写（刷新同主题但包 key 不同时也为 true——单测第一版断言错了，测试抓出来的）。

**改动面**：服务端 `topic-package.ts`（resolveTargetIdentity/inspectTopicImport/applyTopicImport target 参 + 路由解析 multipart 字段）；**三个端点统一补 `fail()`：ApiError → `{error}` 语义化响应**（此前 inspect/apply 抛 ApiError 走 fastify 默认体 `{error:"Bad Request"}`，客户端人话提示全丢——HTTP 冒烟第 10 项抓出来的）；Electron IPC `parent:importTopic` 拆成 `importPick`（只选路径）/`importInspect`/`importApply` 三通道 + preload + `electron/lib/topic-package.ts`（serverUploadWithFields 带字段上传）；web shim 同名三方法（pickFiles 暂存 File 到模块变量）；测试 16→21 例。

**验证**：`test/topic-package.test.ts` 21/21（inspect 三冲突、显式目标导入四处改写、非法组合拒收且不落库、校验矩阵）；web tsc 回基线 5 条（TS2367 收窄误报用顶层布尔 `importing` 消掉——JSX 分支内比较 "importing" 会被当成不可达）；**HTTP 冒烟 13 项全过**（tmp/topic-smoke.sh：inspect none/refresh、显式目标落新目录、400 文案、rename 建议 + 按建议导入；冒烟脚本自己踩过一个 UNIQUE 播种坑——改用 UPDATE 造同名不同 key 场景）。
