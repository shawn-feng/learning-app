## 左侧内容面板 HTML 交互方案讨论（未落地）

背景：左侧 ContentPanel 已从「DOMPurify 消毒 + dangerouslySetInnerHTML」改为「沙盒 iframe（sandbox="allow-scripts allow-modals allow-forms"，不带 allow-same-origin）」，使 AI 生成的 HTML 可运行 JS 交互（番茄钟、点击游戏等），且脚本无法访问父应用 DOM/cookie。

### 讨论问题
如何把 iframe 内 HTML 的交互结果传回父应用（主 React 应用）？

### 结论：用 postMessage
- 唯一既安全又可靠的做法。
- iframe 处于「不透明源」（无 allow-same-origin），无法直接访问父窗口，但 `postMessage` 不要求 same-origin，拿到 parent 引用即可发消息。
- 三种方案对比：
  1. `window.parent.postMessage` — ✅ 能通信 ✅ 沙盒保持，**首选**
  2. 加 `allow-same-origin` 后直接访问 parent — ❌ 破坏隔离，否决
  3. 监听 iframe `location.hash` 变化 — ⚠️ 只能传短字符串，hacky，不推荐

### 拟定协议
iframe 内脚本：
```js
window.parent.postMessage({
  source: "learning-panel",   // 标识来源
  type: "quiz_answer",        // 事件类型
  payload: { correct: true, score: 3 }
}, "*");
```
父应用（ContentPanel.tsx）给 iframe 挂 ref，监听 window message，校验后冒泡到 Learn.tsx：
- 校验 `e.source === ref.current?.contentWindow`（只认自己的 iframe）
- 校验 `data.source === "learning-panel"`（协议双保险）
- 数据当作不可信输入，渲染前转义

### 预留事件类型
- `quiz_answer`：答题结果 → 写学习进度
- `request_tts`：请求朗读 → 触发 TTS 读 payload.text

## 会话历史恢复功能（已落地）

需求：退出孩子模式后再进来，能看到历史会话；用 Pi SDK 原生机制实现。

### 根因
之前 `getChildSession` 用 `SessionManager.create(childDir)`，每次走 `newSession()` 新建空会话，退出时 `dispose` + 删内存缓存，导致对话历史丢失、且每次进入产生孤儿 `.jsonl` 文件。

### 方案（SDK 机制）
- `pi-session.ts`：`SessionManager.create` → `SessionManager.continueRecent`（自动恢复 `~/.pi/agent/sessions/<childId>/` 下 mtime 最新的会话文件）；新增 `getSessionHistory(session)` 提取 user/assistant 文本
- `ipc-handlers.ts`：`pi:start_child` 返回 `{ success, history }`
- `Learn.tsx`：进入时用 history 初始化 messages state

### 上下文长度控制（SDK 内置自动压缩）
- 触发：每次 `prompt()` 前 `shouldCompact()`，`contextTokens > contextWindow - 16384` 时触发
- 行为：保留最近 `20000` token（keepRecentTokens），更旧的用模型总结成摘要
- 注意：SDK 压缩按 token 量倒推，不按时间；「严格最近 24h」的时间维度截断尚未实现（后续如需再加 timestamp 过滤）

### 关键结论（供后续参考）
- `session.messages` 是 getter，指向 `agent.state.messages`
- `continueRecent` 恢复后 sdk.js 会把历史写回 `agent.state.messages`
- 测试需云端服务在 8005 端口（`test/app.test.ts` 用 `CLOUD_API_URL=http://localhost:8005`），否则 `registers parent` 集成测试会 ECONNREFUSED

**测试结果**：29/29 通过
