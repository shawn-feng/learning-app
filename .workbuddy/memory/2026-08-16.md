## 排查：千问 key 保存成功但模型列表无千问

- 现象：添加千问 API key 保存成功，但模型列表没有千问模型。
- 排查：① auth.json 已正确写入 `qwen: {type:api_key,key}`；② 构建产物 out/main/index.js 含 qwen（dashscope/qwen-max/registerProvider）；③ 用 node 22.22.2 跑 .mjs 实测 registerProvider + getAvailable：registerProvider 成功、checkAuth 返回 stored credential、getAvailable 正确返回 qwen-max/qwen-plus —— **代码逻辑正确**。
- 根因：electron 进程 21:08:21 启动，早于构建产物 21:23:57（main）。即 app 主进程仍是旧代码（无 registerQwenProvider）；前端「通义千问」chip 通过 dev 模式 HMR 已热更新，故能保存，但主进程改动需重启才生效 → getAvailable 只返回 deepseek。
- 关键教训：**主进程（electron/）改动后必须重启 app 才能生效，前端（src/ 组件）改动在 dev 模式会 HMR 热更新**。排查时先对比「electron 进程启动时间」vs「构建产物 mtime」可快速定位此类「半更新」问题。
- 处理：已停掉 4 个 electron 进程，用户重启后应正常。
- 附：`pi-coding-agent` 是纯 ESM 包（exports 仅 import，engines node>=22.19），tsx 直接跑会 ERR_PACKAGE_PATH_NOT_EXPORTED，需用 node 直接跑 .mjs 验证。
