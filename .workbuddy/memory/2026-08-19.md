## ISSUE-011 修复：启动卡死（同步扫描 1925 文件阻塞事件循环）
- 根因：`sync-manager.ts scanChildFiles` 全同步 readFileSync 整篇读+sha256 全量哈希+statSync，1925 文件串行独占主进程事件循环；node-cron tick 无法触发（blocking IO WARN）、Chromium network service 失联（crashed 日志）、App 假死。`withTimeout` 救不了：setTimeout 回调同样要事件循环跑，同步阻塞时超时形同虚设。
- 修复（`electron/lib/sync-manager.ts` 重写）：
  1. 扫描全异步：`scanDirectory(rootDir)` 用 fs.promises，每 20 文件 `await setImmediate()` 让出；`scanChildFiles` 变异步返回 `{path,size,mtimeMs}` 不再预先哈希。

  3. size 预过滤：只对「云端存在且 size 相同」的文件算哈希（8 路 mapLimit 并发），size 不同直接 last-write-wins（与原语义等价）。

## ISSUE-014 二次修复（用户实测复现：会话中第二份资料不自动切换）
- 现象：用户手测发现「最近珊珊会话里，第二次 display_content 的资料没自动显示，左侧停留在第一份」。
- 根因（真 root-cause）：会话中自动弹开的旧代码 `Learn.tsx:222` 是「在 `setMaterials(updater)` 闭包里给 `targetId` 赋值 → 同步 `if (targetId) setSelectedMaterialId(targetId)`」——**React 18 updater 异步执行（render 阶段才跑），同步检查时 targetId 恒为 null，自动弹开从未生效**。第一份能显示是恢复逻辑选中的，第二次到达时无切换。初次登记「这条没问题」是误判。
- 修复（Learn.tsx）：① handleToolEnd 的 updater 只做去重/追加，删掉失效的 targetId 闭包与同步 set；② 新增 `useEffect([materials])`：非空时 `setSelectedMaterialId(materials[length-1].id)`，渲染后统一处理「会话中新增 / 恢复回填」两条路径的自动打开；去重返回原引用时 React bail-out、effect 不触发，用户返回列表不被打断；③ 恢复处删掉手动 setSelectedMaterialId，由 effect 统一。
- 通用教训（写进项目记忆）：**不要依赖 setState updater 闭包给外部变量赋值再同步读取**——React 18 中 updater 异步执行，同步检查恒为旧值；需要「状态变更后的派生行为」一律用 useEffect 监听状态。
- 验证：tsc 过滤后 0 业务错误；`npm run build` 通过；全量 vitest 85 用例 72 过 / 13 失败（13 全为既有环境/数据问题，无新增）。ISSUES.md ISSUE-014 记录已更正（含根因说明）。
