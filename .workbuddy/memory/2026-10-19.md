## 部署：客户端 0.1.32 → 201（Ubuntu GUI）

用户要求「把新版客户端部署到 201 上去」。

**前置**：201 原装 `learning-app 0.1.30`（运行中 10 个 xuexihub 进程，桌面会话 shanshan@:0 正常）；`/tmp` 保留 0.1.26/0.1.27/0.1.30 三个历史 deb（回滚用）；磁盘 14G 可用（88%）。

**执行（`tmp/deploy/deploy_client_0132_201.py`）**
- 上传 `dist/learning-app_0.1.32_amd64.deb`（139,168,392 B）→ `/tmp/learning-app_0.1.32_amd64.deb`；远端 sha256 `f515bcd6…dec025` 与本地一致。
- 停旧 GUI → `sudo dpkg -i`（0.1.30 → 0.1.32，update-alternatives 指向 `/opt/学习伙伴/xuexihub`）→ `dpkg -l` 确认 `ii learning-app 0.1.32 amd64`。
- 以 shanshan 重新拉起：`DISPLAY=:0 XAUTHORITY=/home/shanshan/.Xauthority setsid nohup '/opt/学习伙伴/xuexihub' >/tmp/xuexihub-0.1.32.log 2>&1 < /dev/null &`。
- 验证：主进程 170181 起于 17:51:32、PPID=1、共 7 个 xuexihub 进程；`wmctrl -l` 有「学习伙伴」窗口；ffmpeg x11grab 截图确认 UI 正常（身份选择页：家长/珊珊/闻闻/小试）；日志成功标记 `Update for version 0.1.32 is not available (latest version: 0.1.13, downgrade is disallowed).`（Linux 自动升级未接，属预期）。

**踩坑/清理**
1. `pkill -f '/opt/学习伙伴/xuexihub'` 会匹配 SSH 命令自身的 `bash -c` 包装（命令串含该路径）→ 第一次「停旧 GUI」把包装 shell 一起杀了（exit=-1、通道无输出）；旧 GUI 实际已被杀，后续 dpkg 正常。**正确写法：`pkill -f '^/opt/学习伙伴/xuexihub'`（锚定行首）或把 pkill 与启动分成两次 exec。**
2. 启动命令里 `setsid nohup … &` 后跟 `sleep 8; pgrep` 会让 paramiko 通道迟迟不 EOF（残留 bash 包装 PID 170179 处于 do_wait），触发 180s PipeTimeout；启动本身成功。事后 `kill 170179` 清理，GUI 因 setsid 脱离未受影响。
3. 桌面残留 apport「学习伙伴 已意外关闭」提示框（杀旧进程触发）→ `wmctrl -ic` 关闭那个 Ubuntu 窗口（含升级通知），截图复核只剩学习伙伴窗口。
4. 用户数据 `/home/shanshan/.config/learning-app` 未动，登录态保留。

**回滚**：`sudo dpkg -i /tmp/learning-app_0.1.30_amd64.deb` 后按同法重启 GUI。

**关联**：服务端 201 仍为 0.5.39（本次未改），客户端 0.1.32 已含 ISSUE-188/189 全部改动；桌面上看到的身份选择页正常。
