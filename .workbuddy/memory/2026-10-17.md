## ISSUE-187：Mac 孩子端「永远等待模型返回」——201 日志实锤 + 客户端修复

用户报：「珊珊的账号，Mac 上客户端（最新 0.1.30）进珊珊会话，发消息后 agent 一直显示等待模型回复；退出再进消息就出来了；家长 agent 没问题」。

**取证（201 只读，未做任何写操作）**：`server-log.jsonl` + `children` 归属从请求日志反推（珊珊 childId `1f050a7f-df8a-45b0-925a-1ffe2aa35674`，家长 `86a84278…`，Mac 客户端 `192.168.1.101`）。
- 会话 JWT `iat=1791607141 / exp=1792211941` = **10-10 12:39 → 10-17 12:39**（7 天 TTL，app 一直开着）。
- **13:07:21 唯一一条 `GET /agent/…/stream?…&lastEventId=28787` → 401**（休眠/网络抖动后重连，带过期 token）；此后全天**再无 stream 请求**。
- 17:27 `auth/parent-status` 401 → 17:28 抖音重登 → 17:28:56 `/open` 200 → 17:32/17:33:38 `/prompt` 200（服务端正常跑）→ 17:33:23/27、17:38:01/03、17:39:13 多次 `/abort`（用户等不到输出点停止，其中一轮等了 4 分 23 秒）→ 17:38:12 再登录 → 17:38:33 `/open` **历史里有前面几轮的回复**（=「退出再进就显示」）→ 后续 prompt 依旧静默。
- 家长流是 17:38 重登后才建立 → 所以家长正常；坏的是**登录前就存在的孩子流死句柄**。

**根因**：`openSse` 401/403 时置 `closed=true`（不重连、不报错）但 `StreamHandle` 只暴露 `close()`；`ipc-handlers` 的 `ensure*Stream` 只判 `agentStreams.has(key)` ⇒ 死句柄永久占位，重新登录也不重建。Web 端（`web/src/shim/core/sse.ts`）早有 `closed` 判据，Electron 漏了。触发条件 = 7 天 token 在长开 app 内过期 + 任意一次 SSE 重连。

**修复（客户端主进程，服务端零改动）**：
1. `server-agent-client.ts`：`StreamHandle` 加 `readonly closed`（getter）+ 401/403 留日志；
2. `ipc-handlers.ts`：`dropClosedStream` → `ensure*Stream` 改「活句柄才复用」；新增 `resetAgentStreams` 在 login/register/verify/douyin-login/logout 关闭清空（顺带修「换账号后 parent 流复用旧账号连接」隐患）；
3. `package.json` 0.1.30 → **0.1.31**（待打包）。

**验证**：新增 `test/issue187-sse-closed.test.ts` 4 例（401/403 置终态、正常连接 closed=false、close 后置位、事件帧解析且不重连）+ 既有 `server-agent-client` 27 例 = 31/31 绿；`npm run build` 主进程/预加载通过、产物含 `get closed()`；tsc（server 侧 TS 5.9）无新增错。⚠️ 本机渲染层构建稳定报 `[vite:esbuild-transpile] remove …: Access is denied`（esbuild 退出删临时二进制被拒，换 TEMP 也复现；本轮未改渲染层）——Mac 包请在 macOS 侧构建验证。

**遗留建议（未做，需用户拍板）**：① `/auth/license` 回签新 session token 做滑动续期（服务端改动 + 部署 201），根治「长开 7 天后全端 401」；② Electron 也发 `pi:sse_state` 并把 `ChatWindow` 的 `sseDown` 接上（目前是死代码），让断流/掉登录在聊天区可见。

## 用户追问：「断流/掉登录之前不是修过吗？」——逐条核查既有修复的边界（记入 ISSUE-187 §八）

- **ISSUE-096（09-14）**：修的是「断线从不重连」，但正文明确「401/403 终止」→ 401 被当成终点；且只改 `openSse`，没动 `ensure*Stream` 的 `has()`。
- **ISSUE-145（09-24）**：修的是**静默停摆**（连接活着、心跳照写、JS 零消费、无 done 无异常）；本案是显式 401，不是同一路径；145 的重连仍用过期 token，重连即 401。且 145 自己写了「Electron 未暴露 `pi:sse_state`，桌面端无横条」。
- **ISSUE-167/179（09-28 / 10-13）**：修的是**服务端不可达**（fetch 抛错 → 记账 → `/health` 探活 → 恢复）；401 = 拿到响应 = 可达，探活/阻断都不触发。
- **ISSUE-160（09-27）/ ISSUE-164 追加（10-08）**：修的是 **license 授权层**（刷新被踢、任务门禁），与 session JWT / SSE 无关。
- **平台差异**：`closed` + `disposeChild` 只在 web shim（`2f7dac6` 起）；`git log -S "readonly closed" electron/lib/server-agent-client.ts` 为空 ⇒ 桌面端从没有"401 后重建"这一格。
- **为什么这台 Mac 中招**：①app 从 10-10 长开 7 天，JWT 12:39 到期；②`.101` 网络每 30~60 分钟微抖（ISSUE-179 实测 3 天 62 次探活），13:07 一次重连带过期 token → 401；③重新登录只换 HTTP token，死句柄不重建 → 4 小时 `/prompt` 全 200、客户端 0 事件。
- **结论**：旧修复没有失效，是边界没覆盖；本次补的就是「401 终止后的重建责任 + 登录/登出重置流」。
