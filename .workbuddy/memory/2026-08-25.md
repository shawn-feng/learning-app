## 架构转向：云端只做消息交换，不做数据存储（2026-08-25 16:5x，用户拍板）
- 用户决策链：① 去掉云端备份（不推资料上云、不做版本历史）→ 多 PC 用本地 zip 备份+导入恢复；② 跨机分发课程 + 进度查询要保留，但**只传「要分发的数据」到本地再写库**；③ 分配包**只传数据不传文件**（html/mp4 靠 zip 迁移）；④ 进度摘要**仅被请求时**生成上传。
- 新架构：云端 = 消息交换层（非备份）：
  - `sync_deliveries`：分配包暂存（parent 上传 → child 拉取 → 本地写库 → ack 即删）。分配包 = {topicDir, topicName, rules, method全文, courses:[{title,sortOrder,material,tags,lessonMethod,htmlPath}]}，不含文件。
  - `sync_progress`：进度摘要（child 生成 JSON 上传，只留最新；parent GET 读）。
  - **删除**：整库云同步（syncAllChildren/syncChild/pushChildChanges/fullSnapshot）、家长空间(_parent)、版本历史(versions/restore)、/children 新机拉回、send_materials/assign_topic 事件（分配=上传分配包本身）、云端查进度改为读摘要。
- 进度安全核心：**kb.sqlite 永不整包跨机**；家长端 parent:allocate 只生成包上传（不再改孩子库副本）；孩子端在自己最新 kb.sqlite 上合并（allocateTopicToChild 本身 DB 级合并，status/mastery 保留）。
- 保留：本地 zip 备份/恢复/定时备份（多 PC 迁移通道）、事件轮询机制（改为轮询 deliveries+progress request）、eventPoll 配置 UI。
