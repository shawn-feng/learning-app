## ISSUE-114 线上事故：「错题本两端全空」——web shim 返回形态与 IPC 契约不一致（已修复并部署 201）

**现象**：用户报告本地开发环境与 201 生产上，孩子/家长界面的错题本都是空的（昨天还看得到）。

**排查（数据全程无恙）**：
- 本地服务端 `server/data/kb/86a84278…/1f050a7f（珊珊）.sqlite`：mistake_book **13 条**（至 09-27）；
- 201 `/opt/learning-server/data/kb/.../1f050a7f….sqlite`：**231 条**，09-29 早上还在新增（孩子在学）；
- 两端 HTTP 直测（自签家长 JWT）均 200 + 正确返回数据 → 排除数据丢失/服务端读路径；
- 服务端日志显示今天用户客户端零请求打到本地 → 用户看的是 **web 端**（本地 dev 经 vite 代理 / 201 同源）。

**根因**：`web/src/shim/domains/ops.ts` 的 `mistakesList` 返回扁平 `{success, mistakes}`，而组件（MistakeBookModal/ChildMistakeBook）按 electron IPC 契约读 `r.data?.mistakes` → HTTP 200 拿到数据仍渲染空列表；`mistakeAction` 同病（`data.ok` 缺失 → 成功误报失败）。electron 走真 IPC（ipc-handlers 包 `data`）形态正确——「昨天还能看到」= 昨天看的是 electron 客户端（09-27 22:08 最后一次孩子端 GET 200）。拉 201 线上 bundle 实锤含扁平代码 `success:!0,mistakes:`。

**修复**（commit 6317cc3）：shim 三方法（list/report/action）返回 `{success, data}` 对齐 ipc-handlers；web typecheck ops.ts 清零（其余 6 行报错为存量，与本次无关）。

**部署**：`tmp/deploy/deploy_web_mistakefix.py` → 201 `/opt/learning-server/web/dist/`（新 index-iC1EsYe6.js，sha256 校验一致，HTTP 200；远端目录无创建权限没做成时间戳备份，但旧 bundle `index-BsQYiFoy.js` 未删+本地留有副本可回滚）。
- ⚠ 本次部署**顺带带上了工作区里 ISSUE-165 的 web shim（voice.ts 服务端转录+浏览器听写降级）与开放 API 密钥设置 UI**（09-28 会话的已验证构建产物）。201 服务端仍是 0.5.17：web 语音会先打 /asr/transcribe 404 再降级浏览器听写（链路有兜底）；「设置→开放接口」会因 /apikeys 404 报错——**0.5.18 服务端部署后自愈，两端需成对升级**（09-28 日志既有结论）。

**方法论教训**：web shim 的存在意义 = 逐通道对齐 electron IPC 返回形状；新加 shim 方法时返回形态必须照抄 ipc-handlers 的包裹层（`{success, data}`），否则 electron 里验证通过的 UI 到 web 全静默失效（组件对 success=true 下的缺字段只会渲染空/失败，不报错）。
