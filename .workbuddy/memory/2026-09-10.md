## 09:40 ISSUE-068 修复：停止 agent 后仍报 "Agent is already processing"
- 根因（已确认）：SDK 在 `isStreaming` 且调用方未传 streamingBehavior 时抛 "Agent is already processing"；前端 handleStop 在调 piAbort 后**立刻** setBusy(false) 显示「已停止」，但 SDK 会话 isStreaming 要等底层流真正终止（abort 内部 await waitForIdle）才清零，于是「已停止」窗口内重发消息命中 SDK 重入守卫。
- 两层防御：
  - Layer 2（主进程兜底）：`ipc-handlers.ts` 的 `pi:prompt`/`pi:prompt_parent`/`pi:prompt_parent_content`/`scene:prompt` 入口顶部加在途拦截——对应 `*PromptAbort` 非 null 即 `return {success:false, error:"上一条消息还在收尾或停止中，请稍候再发。"}`。其中 `pi:prompt_parent_content` 原本**无 abort 登记**，本次补上 `parentContentPromptAbort` 变量 + 登记 + stopped 跳过回发 + finally 复位，并在 `pi:abort` 增加 `parent-content` 分支。
  - Layer 1（前端锁）：`Learn.tsx`/`ParentChatPanel.tsx` 加 `stopping` 态，handleStop 不再立即解禁，等 reply_end 才解禁；所有结束/错误事件解禁时一并清 stopping；按钮 disabled/running 改 `busy||stopping`；加 5s 安全兜底防卡死。
- 验证：tsc 仅环境级全局类型噪音、编辑文件零报错；复现（长思考点停止→立刻重发）应不再出现英文原错，改为按钮「停止中」禁用或中文友好提示。ISSUE-068.md + ISSUES.md 索引已标 ✅。
