## Mac 安装报"该 Mac 不支持这个应用"的根因与修复

- 用户 macOS 12.7.6 安装 run `32912746576` 产物后报"该 Mac 不支持这个应用"。
- **根因**：GitHub `macos-latest` 是 Apple Silicon 机器，默认打出 **arm64-only** dmg；该错误只在 **Intel Mac** 上出现（Apple Silicon 能原生跑 arm64）→ 证明用户为 **Intel Mac**。Electron 43 最低系统 10.15，12.7.6 满足，非版本问题。
- 尝试 `arch: "universal"`（x64+arm64 通用）：run `32916756398` 构建失败，报错 `Detected file ".../pi-tui/native/darwin/prebuilds/darwin-arm64/darwin-modifiers.node" that's the same in both x64 and arm64 builds` —— 依赖 `@earendil-works/pi-tui` 的原生 `.node` 被同时打进 x64/arm64 两临时包，universal 合并阶段无法区分。
- **最终修复**：`build.mac.target[0].arch` 改回 **`"x64"`**（单次打包不经 universal 合并，绕开冲突）；保留 `minimumSystemVersion: "10.15"`（防 Runner 抬高最低版本误拦旧 macOS）。x64 在 Intel Mac 原生运行、Apple Silicon 经 Rosetta 2 兼容。
- 提交 `a4b3beb` 推送 master；`gh workflow run "Build macOS"` 重跑 → run `32916998192` **success**（1m43s，全绿），产物 x64 dmg 已可下载。
- PACKAGING.md §9.1 / §9.5 已更新为 x64 决策与原因。
- **教训**：electron 项目若含把某架构原生模块同时塞进所有 arch 包（如 pi-tui）的依赖，universal 打包会合并失败；此时对 Intel 用户直接打 x64 更简单可靠。

## BUG 修复：html 资料 CSS/JS/图片不加载（srcDoc 相对路径失效）
- **症状**：英语课程的 html 学习页（materials/english/NN-标题/index.html），CSS 样式完全没加载（JS 同理）。
- **根因**：`src/components/TopicDetail.tsx` 的 `StudentMaterial` 用 `<iframe srcDoc={content}>` 渲染课程 html 文件。srcDoc 的文档 base URL 是 `about:blank`，html 里的**相对资源**（`../wowenglish.css`、`../enhance.js`、`../episode.js`）解析到 `about:blank/..` 而失效；视频能播只是因为它用绝对 `media://` URL，与相对路径无关。**这是系统性坑**：任何带相对引用的资料都受影响（如 hanzigong 的 `../images/*.gif|png` 笔顺图此前也默默失效）。
- **修复**：让 iframe 直接加载文件自身的 `file://` URL，相对资源自然相对文件目录解析。
  - `electron/lib/parent-library.ts` 的 `readParentMaterial` 新增返回 `fileUrl: pathToFileURL(resolved).href`（node:url，正确编码中文 Windows 路径）；
  - `StudentMaterial` 对 html 文件分支改为 `<iframe src={fileHtml.fileUrl}>`（保留 `sandbox="allow-scripts allow-same-origin"`）；`sendMaterial` html 片段分支仍用 srcDoc（无文件路径，按设计应自包含）。
  - IPC `parent:readMaterial` 透传 data 对象，`fileUrl` 自动随 `data` 返回，preload 无需改签名。

## ⚠️ 上方案被推翻（同日复测）：src=fileUrl 导致所有主题资料空白 → 改 asset:// 协议方案
- **新症状**：用户反馈「现在所有学习主题的学习资料都无法正常显示了」（即上面 src=fileUrl 方案上线后）。

- **最终方案（已验证）**：新增 `asset://` 协议 + 相对引用改写 + 继续 srcDoc：
  1. `electron/lib/media-protocol.ts`：新增 `resolveAssetTarget` / `buildAssetUrl` / `registerAssetScheme` / `registerAssetProtocol`。`asset://local/parent/{pid}/{topic}/{rel}` → `data/parents/{pid}/materials/{topic}/{rel}`，白名单扩展名(css/js/图片/字体/html/json 等)，防目录穿越；特权同 media(standard+secure)，可从 dev http 源访问。

  3. `src/components/TopicDetail.tsx`：StudentMaterial 回退为 `<iframe srcDoc={fileHtml.content}>`（内容已是改写后）。
  4. `electron/main.ts`：ready 前 `registerAssetScheme()`、ready 后 `registerAssetProtocol()`。

## ⚠️ 二轮修复：asset:// 协议 handler 的 URL 解析 bug（英语/汉字宫仍不加载的真凶）
- **症状**：asset:// 方案上线后，英语 CSS、汉字宫笔顺图依旧不加载（taodi/xiaozhuan 无相对引用所以正常）。
- **根因**：`resolveAssetTarget` 把 `new URL('asset://local/parent/...').pathname` 当成 `/local/parent/...` 解析——但 asset 是 standard scheme，`local` 是 **host**，pathname 实际是 `/parent/default/english/wowenglish.css`。代码检查 `segs[0]==='local'` 永远不成立 → 每个 asset 请求都 403。media:// 的 `resolveMediaTarget` 一直检查 `segs[0]==='parent'` 所以没踩（local 不在 pathname 里）。
- **修复**（electron/lib/media-protocol.ts）：`resolveAssetTarget` 改为 `segs[0]==='parent'`、`parentId=segs[1]`、`topic=segs[2]`、`rest=segs.slice(3)`。
- **顺带修复**：`registerSchemesAsPrivileged` 官方要求只调用一次，原代码 media/asset 各调一次可能互相覆盖 → 合并为单次 `registerCustomSchemes()`（一次注册 media+asset），main.ts 同步改。
- **验证**：test_asset_rewrite.js 改为用 `new URL()` 取 pathname 模拟真实 handler——english 每课 5 asset + 1 media、hanzigong 12 asset + 1 media、taodi/xiaozhuan 仅 media，全部命中磁盘文件（missing=0）；tsc 5 条已知告警；rm -rf out 后 build 全绿；bundle 确认 registerCustomSchemes 单次注册 media+asset、旧函数已移除。
- **经验**：自定义 standard scheme 的 URL 解析测试，必须用 `new URL()` 验证 host/pathname 拆分，不能凭字符串直觉（media:// 老代码是正确范例）。
