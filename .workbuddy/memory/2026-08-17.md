## 排查：千问 flash/plus 比 deepseek 慢（定位 + thinking_budget 修复）

- 现象：qwen-flash/plus 比 deepseek-v4-flash 慢很多。
- 排查方法：直接流式调 DashScope + DeepSeek 官方 API，计时各阶段（首 chunk / 思考 reasoning_content / 正文 content 首 token / 总耗时）。
- 结论：慢在「思考阶段」，不在网络（首 chunk 都是 0.2~0.4s），也不在正文生成：
  - deepseek-v4-flash：思考仅 ~158 字符/1s，正文首 token 1.7s，总 7.8s。
  - qwen-flash（enable_thinking=true）：思考 ~1900 字符/10s，正文首 token 9s，总 15s。
  - qwen-plus：思考 ~1900 字符/18s，正文首 token 18s，总 34s。
  - qwen-flash（enable_thinking=false）：无思考，总 6.2s（快），但复杂 agent 任务会把思考写进 content（问题2复发）。
- 关键发现：reasoning_effort 对 qwen3.7 无效（low/medium/不传 思考都是 ~1900 字符）；阿里云文档确认 qwen3.7 用 thinking_budget（限制思考 token 数）而非 reasoning_effort（那是 deepseek-v4/qwen3.8-max 的参数）。
- 修复（pi-runtime.ts）：qwen-plus/flash 加 samplingParams:{thinking_budget:512}。实测 flash 思考 1821→770 字符、总 12.2s→7.4s（≈deepseek）；plus 思考 1696→779 字符、正文首 token 15.9s→8.4s。qwen-max 不加（实测 max 本就不思考、思考 0 字符，加了反而变慢）。
- 验证：抓 payload 确认 enable_thinking:true + thinking_budget:512 共存（samplingParams 不含 enable_thinking，不覆盖）；构建✅ 测试 28/29（1 失败为既有 8005 云端注册）。
- 遗留：plus 总耗时仍 ~24s（正文生成本身慢，模型比 flash 大），只能缩短思考段、无法赶平 deepseek；如需更快可考虑用 flash 或进一步调小 budget。
