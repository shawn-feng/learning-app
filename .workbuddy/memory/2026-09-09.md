## 15:00 阿里 SSECP JS SDK 文档(2873513) 关键发现（纠正此前误判）
- 文档是**纯浏览器端 JS SDK**（`engine.js`，控制台下载，`window.EngineEvaluat`），非服务端 SDK。

## 16:17 阿里长文本限制实测：无字符数上限，仅"内核超时"受音频对齐影响
- 用户问背诵文本长度限制（时间 vs 字符数）。对照实验脚本 `.workbuddy/tmp/ssecp-longtext-test*.mjs` + `ssecp-duration-test.mjs`（真实 ssapi.txt 凭证）。
- **结论：阿里/声希 `cn.pred.score` 没有字符数硬上限**。文本 800/1000/1200/1500/2000/4000 字全部要么返回 result，要么失败于 `"error":"core is timeout"`——**从未出现"文本过长/refText exceeds"类错误**；4000 字返回 OK。
- `core is timeout` 是**服务端内核处理超时**，由测试用的**纯合成正弦波里没有真实语音**导致（内核等不到能与 refText 对齐的语音而超时）；与文本长度无单调关系（4000字反而过，1500字反而 timeout 是噪声）。真实场景学生读全文、语音对齐则不会触发。
- **时长**：固定10字短文本 + 递增音频，180s 确认 HTTP 200（首轮 B 组实测 overall=0）；更长(300/600/900s) 在测试机因上行带宽/服务端负载把上传拖过 180s fetch 超时，属测试环境限制，**非服务端拒绝**，未证出硬时长天花板。
- **对实现的影响**：阿里分支**不需要**腾讯那种 30/120 字 eval_mode 降级或超长按句拆分（`aliyun-ssecp.ts` 当前无长度拆分逻辑恰好正确）。唯一注意点：录音时长须与文本大致匹配（别用 3s 短录音对 1000 字背诵），否则可能 `core is timeout`。腾讯的 >120 字拆分限制**只适用于腾讯**，不适用于阿里。
