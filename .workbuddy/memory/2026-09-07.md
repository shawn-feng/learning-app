## ISSUE-062 设计讨论：用「会话树分支」让课程/主题成 pi 树的一支以省 token 缓存（已记入 ISSUES.md）
- 用户提问：能否一个课程/主题是 pi 会话树的一个分支来省缓存消耗。
- 现状确认（已读 pi-session.ts）：当前每课是**独立 .jsonl 文件 + newSession()**，不是树；SDK 两原语 `newSession`(独立文件/不共享前缀) vs `resetLeaf`(同文件分叉/共享祖先前缀)。token-stats 已追踪 cacheRead/cacheWrite。
- **反直觉核心结论**：① 主流 provider 的 prompt cache 按前缀内容哈希**全局去重**（跨文件）→ 当前各课完全相同的 system prompt 前缀**已在跨文件命中 cacheRead**，未必需要树；② 树能省的「额外」缓存=共享对话历史前缀，而这正是 ISSUE-029/054 刻意不共享的（防串味）；③ 当前 `courseLesson`(教法) 被注入 systemPromptOverride（buildChildPrompt 第5参，:620）致每课前缀不同，反而挡住共享——这是比「是否用树」更前置的问题。
- 收益三钳制：provider 是否支持 prefix caching、TTL 分钟级(跨天失效)、前缀稳定性(日期注入变前缀即失效)。
- 收敛建议：**不急于改树**。先①看 token-stats 的 cacheRead/write 占比验证；②把 courseLesson 移出缓存前缀。若一天内多门课 cacheWrite 高才考虑树(主会话作树根、每课 resetLeaf 从根分叉)，但需解决分支累积/导航 UI/reset 语义/provider 支持。树净收益有限、与按课隔离目标有张力 → 标记「待数据验证优化项」。
