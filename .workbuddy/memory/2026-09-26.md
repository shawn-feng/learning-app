## 记录 ISSUE-152：评估类判断支持「自然语言标准 + LLM 判断」（用户提出，待拍板）

- **用户原话要点**：在一些需要评估的地方，可以用自然语言调 LLM 进行判断。例如背诵题，阿里云返回了分数，分析这个分数的标准可以是自然语言——现在代码写死 90 分以上是通过，有的课程可以是 85 分。这样的地方应该提供自然语言 + LLM 的判断方法，判断后按照要求填写结果就行了。
- **代码核实**（已写进 issue 的现状表）：
  - 背诵/朗读题判定在客户端写死：`src/components/ExamView.tsx:467` `const pass = Number((q as any).recitePass) || 90; correct = total >= pass`——`recitePass` 是纯数字（主题方法/排期可覆盖，默认 90），能配 85 但表达不了组合标准；pointGot 线性换算（`:469`）与 aiComment 模板（`:475`）同样写死。
  - 阿里云 SSECP 分项其实很全（`SpeechAssessment`：overall/pron/accuracy/integrity/fluency/prosody，`electron/lib/exam.ts:388`），现在只用总分一个数。
  - 同场考核口径割裂：文字题已是「LLM+rubric」判分（`server/src/agent/exam-engine.ts:141`），重考标准 retake 已是自然语言（ISSUE-115，`electron/lib/exam.ts:304`），唯独背诵题留在客户端数字阈值。
- **issue 建议（待拍板）**：方法/排期加自然语言标准字段（如 reciteRule，缺省回落 recitePass 默认 90）；SSECP 评测后把分项+标准交判分 LLM 下结论，输出 correct/pointGot/aiComment，客户端只回填；LLM 不可用回落数字线（软失败先例 `ExamView.tsx:419`）。与「未做」里的 `assess_method_set` 同属考核方法域，实施时可一起设计。
