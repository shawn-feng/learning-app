## KB P2.1 优化：真实账号端到端实测之后（2026-09-25）

**做法**：用真实账号（`test@qq.com`，孩子「珊珊」）+ 真实模型把 P1/P2 完整跑了一遍（服务端 8788 + Web 5173）。
主线**全部通过**（家长口述→草稿→发布→孩子命中→高风险拒答→缺口落库→挂课→进课注入），
但**测出两个缺陷 + 挖出一个既有严重缺陷**——都是"看代码看不出来、只有真跑才暴露"的那类。

- **缺陷 1：条目删不掉**。全仓唯一的 `DELETE FROM` 是解绑链接用的，`kb_entries` **没有任何删除路径**。
  → `deleteKbEntries()` + `parent_kb_save` 的 `delete` 参数（折进 save，与 `risk_terms` 同理由：省一把常驻工具）。
  **唯一不变式：只能删「此刻孩子看不到的」**——**把不可逆的动作排在可逆的动作之后**（撤回可逆、删除不可逆）。
  连带清理三处（无外键）：`kb_entry_assets`、`kb_entry_links`，以及
  **`kb_gaps.entry_id` 回填过的缺口重新打开**（答案销毁了，那问题就重新是没人回答的问题，不留"已闭环"的假象）。
- **缺陷 2：撤回收不回已经说出去的话（本轮最值得记的一条）**。
  实测：撤回「恐龙是怎么没的」后，**同一个会话里再问，孩子仍然说得出家里那句专属说法**
  （`天上掉石头那一回`），**那一轮没有任何 `kb_lookup` 调用**。
  → **门控管得住"查得到查不到"，管不住"还记得不记得"。**
  **修法分两层**：① 每轮往 system prompt 追一段复核纪律；② **撤回指纹一变就往会话里插一条消息**（`display:false`）。
  **为什么两层都要**：先只做 ① → **模型完全无视**，连库都不查，照样复述，还说"我的答案不会变哦"；
  加上 ② 之后同一场景立刻变成 **先 `kb_lookup` → 命中不到 →「我一时记不清了，得去问问爸爸妈妈」→ 主动换话题**。
  → 教训：**system prompt 后缀压不住会话里已经形成的模式**；要改"正在进行的行为"，得在更靠近当前提问的位置说话。
  **刻意不做**：不把"被撤回的条目名"注入进去（更硬但**凭空扩大暴露面**——撤回的条目里就有
  「教师用书上怎么说的」这种家长不想让孩子知道存在的东西）；现在不泄漏任何标题，且用既有门控工具当执行点。
- **挖出的既有严重缺陷：`extensionFactories` 这根线从来没接通**（排查 ② 为什么没生效时发现）。
  SDK 唯一的读取点是 `DefaultResourceLoader` 的 `options.extensionFactories`，而
  **`createAgentSession()` 根本没引用 `options.extensionFactories`**；`packages/agent-core/src/sessions.ts`
  恰恰是"自建 loader + 把 extensionFactories 传给 createAgentSession"——**传错了对象**，
  且 `loadExtensionFactories` 把工厂异常收进 `errors` 而不抛，**连报错都没有**。
  → 后果：`learning-guard` 在整个 agent-core 会话路径上**一直没被加载**（「每轮注入当前日期」与
  「fs 路径越界红线兜底」都是死的），与它自己注释里记的那次实测（跨天沿用旧日期）症状一致。
  → 修法：交给 **`ResourceLoader`**（真入口），去掉 `createAgentSession` 上那个无效选项，两处写明原因。
  **这是一条跨模块的行为变更**：修复后所有服务端孩子会话（含 programming agent）真的会加载守卫。
- **缺陷 3：进课注入措辞有歧义**。问「这节课爸爸妈妈给我准备了什么说法吗」，模型去读教法、**没提**注入的条目

  `getGatedEntry()`（按 id **再过一次门控**读：旁表向量是写入那一刻的快照，家长后来可能撤回/改草稿/删了）。
- `markStale` 挂在**调用层**（`parent-kb-tools.queueEmbed`），`kb-entries.ts` 保持纯数据层。

**两处只有真跑才发现的修正**（这次是拿真账号 + 真 embedding 跑出来的）：
1. **语义命中一开始被我当成权威口径直接返回**（复用精确命中格式，含「依据：家长口径（可直接引用）」）——
   但语义命中可能是**话题相邻**而非同一件事（问"月亮"命中"太阳"），那等于让家长为**另一个问题**认过的话
   冒充这个问题的口径，**比没答上来更糟**。→ 新增 `formatSemanticHits()`：只作**候选提示**，
   且**块内那行也要改**（块内「可直接引用」与块外「先判断」会打架，模型听块内的），并给三条退路。
   与仓库既有约定同源：`formatCandidates` 注释写着「只提示不代入」。
2. **沿用 0.6 阈值不对**：那个值是为「课程名→课程名」（短、近同形）调的；
   实测 `很久以前地球上那些特别大的动物后来都去哪儿了` 对 `恐龙是怎么没的` 只有 **0.5119**
   ——语义上明明同一件事却被拒。→ 新增 `KB_VECTOR_THRESHOLD = 0.45`（家长显式配 `embeddingThreshold` 时以家长的为准）。
   调低的代价由修正 1 补回来。

**实测证据**：provider `qwen / text-embedding-v4`、dim 1024、向量落旁表；
孩子换问法（精确 0 命中）→ 语义命中 0.51 → 模型**先问「你说的是不是恐龙呀？」**再引用家长原话，
说得出是爸爸妈妈准备的，未编造内容。
中途还意外验证了两条 P2.1 机制：那条当时处于"已撤回"状态时，**门控正确挡住语义命中**，
且撤回提醒让另一个孩子的会话**拒绝回答并改口去问爸爸妈妈**。

**验证**：新增 `test/kb-p3-vector-recall.test.ts` **19 例**（合成文本不落库 / body 截 600 /
**向量能排序但门控说了算**（草稿·已撤回·share 只给别的孩子·行已删）/ 阈值与 topK /
语义回话契约（不含"可直接引用"）/ 家长显式阈值优先 / 失败静默降级）。

—— 与上一轮**逐项一致**，零新增失败。

**已知缺口（阶段②一并解决）**：本轮之前的条目没有向量（只有被更新过的才会排队重建）→ 需要 backfill。

## KB P3 阶段②：入库管道（2026-09-25）

**入口**：`parent_kb_save({ ingest: [{ path, title?, entry_id?, entry_title? }] })`
（折进 save，与 `risk_terms`/`delete` 同一理由：都是"落库"这类动作，省一把常驻工具）。

**四条设计约束**：
1. **提取产物永远不是权威**——提取只能产出「描述」产不出「指令」（§3.4.1），所以正文只进 `body`，
   `summary` 永远留给家长；`kb_lookup` 也**从不返回 `body`**。`body` 的用途是**给向量召回提供匹配面**
   （"换个问法也能找到这条"）+ 让家长看到"这份资料讲的是什么"。
   **代码化**：`body` **不算**"有内容"，只有正文的条目**必须被拒**（否则孩子问到时什么都拿不到）。
2. **同步、不做 worker**。html/md/txt 文本化是纯本地毫秒级；做成队列只会让"家长说一句、等半天"。
   §5.1 写的"入库管道（worker）"留给**重活**（PDF 解析、图片 OCR、网页抓取）。**别为对齐文档措辞把快事做成异步。**
3. **不支持的格式如实报错**（PDF/图片）并给出路（让家长口述要点，或先按"只有资料"的条目挂上）——
   **绝不返回空正文**让上游以为成功了。PDF 要引纯 JS 依赖（§5.5.3 风险 2 明写"打包阶段实测"），
   图片要走视觉模型 → 两者留作单独增量。
4. **html→文本先删 `script`/`style`/注释再剥标签**（反过来会把 js 源码当正文灌进 `body`，向量被变量名污染）。

**顺带修掉一个既有数据损失隐患（重要）**：`saveKbEntries` 原先把 `undefined` 一律当"清空"——
于是"只想加个别名"会**抹掉家长的 `summary`**，"只想改说法"会把 `share` 从「只给某个孩子」**放宽成「所有孩子」**，
两者都**静默**发生。改成 **patch 语义**（`undefined` = 不改动库里已有的值，清空要显式传 `""`）；`body` 同一套语义。
P1 既有测试无一依赖旧语义，零回归。

**实测修掉一个真 bug**：模型会把 `entries` 与 `ingest` 放**同一次调用**里（"建一条条目，正文从这份 html 来"）。
最初两者**分两次落库** → 第一趟里那条 `entries` 既没说法也没资产 → 被「至少要有一样」拒掉，
而它的资产本该由同一趟的 ingest 提供。**同一批意图必须走同一次校验** → 改成合并成一次 `saveKbEntries`。

**backfill**：`markStale` 只在写入那一刻排队 → **本轮之前的条目一条向量都没有**，语义兜底对它们等于不存在
（**静默的功能缺失，最难发现的那种**）。现在在 `parent_kb_list` 里顺手 diff 一次补齐。

**实测证据（真账号 + 真模型）**：
- 家长放 `guoxue/恐龙小知识.html` 说"收进知识库" → 助手**先列清单、读内容、再复述确认**（A7 生效，没直接落库）；
  确认后 `ingest` → 草稿建成：`body` 178 字、**不含文件里的 script 变量**、资料已挂、`origin=generated`。
- 合并修复后：`{entries:[{title,aliases,usage}], ingest:[{path,title}]}` 一次调用里
  **`usage` 与 `body` 都生效**（验证了那个 bug 确已修掉）。
- **最值的一幕**：把「甲骨文小知识.html」收进库时，助手**主动指出资料里有一段正是家长交代过不要讲的内容**
  （"1899 年王懿荣认出甲骨文" vs 家长定的"别讲谁发现的"），并给出三个处理法让家长选
  ——**知识库在这里当成了一道"口径与资料对不上"的检查**。

**验证**：新增 `test/kb-p3-ingest.test.ts` **22 例**（文本化四条取舍 / 截断标记 / 不支持格式报错给出路 /
`body` 的 patch 语义与"只正文必须被拒" / ingest 工具路径（含灌进已有条目**不改名**、不存在要报错）/
**entries+ingest 同一次调用** / backfill 不破坏清单）。KB 受影响面 **11 文件 / 221 例全绿**；
全量 `npx vitest run` **66 passed / 8 failed（750 passed / 15 failed）**——与前两轮**逐项一致**，零新增失败。
工具块 16541 / 上限调到 17000（+357 全是 `ingest` 的参数结构）。

**留给下一轮**：③ `kb_entry_chunks` 分块 + 块级向量；④ 网页落袋（§5.3）；
PDF/图片提取（要引依赖 / 走视觉模型，需单独决策）。

## KB P3 阶段③：长正文分块 + 块级向量（2026-09-25）

**要解决的问题**：条目级向量把 `body` 截到 600 字，一份两万字资料里**第 600 字之后的内容在条目向量里根本不存在**。

**三个设计点**：
1. `kb_entry_chunks` 是 **body 的缓存**、不是第二份真源：**写 body 就整体重建**（分块是 `body` 的确定性派生；
   增量更新要在 `seq` 上维持一致，代价远大于 delete+insert）。正确性判据：**任何时候都能由 body 完整重建**
   → 所以**删条目必须连块一起删**，否则留下永远重建不出来的孤儿。
2. 仍然**落一张表**：块要当**向量旁表的主键载体**（`row_pk = [entry_id, seq]`），而 `markStale`/`topVectorRows`
   这套既有设施需要一个能按主键查回文本的**真实表**。分块算法留在 `kb-ingest.ts`，db 层只存它拿到的东西。
3. **写入顺序：先同步分块、再排向量**。块的 `seq` 由刚写进去的 body 决定；先排队再重建的话排出去的是**旧 seq**，
   worker 会拿它查到**另一段文本**。**索引的输入必须先落地。**

`chunkText`：段落优先（短段落尽量合并）→ 超长段落按句切 + 60 字重叠 → 去重复块 → 上限 64 块。
两个实测细节：`size` 下限夹在 80；硬切时**不再吐"已被前一块覆盖的尾巴"**（否则切出「。」这种 1 字块——测出来的）。
召回：条目级与块级**都查**，按 entry_id 合并取最高分，再**逐条过门控**读当前状态（命中的仍是**条目**不是片段）。

**⚠️ 一个必须如实记的实测结论：块级的收益是「排序置信度」，不是"硬性救回"。**
方案预期是"第 600 字之后的内容根本不在条目向量里"——**前提对**（嵌入文本确实只有 638 字），**但结论比实际强**。
真 embedding 实测（两份长文档 + 指向正文尾部的问句）：

| 文档 | 问句 | 条目级 | 块级 |
|---|---|---|---|
| 古代文字小史（标题点题） | 秦朝把文字统一成了什么字体？ | 0.5932 | **0.7028** |
| 同上 | 「隶变」说的是什么事？ | 0.5893 | **0.6880** |
| 周末家庭活动汇编（异构、标题不点题） | 蜜蜂为什么会跳八字舞？ | 0.5359 | **0.7649** |

**条目级三条都过了 0.45 阈值**——因为条目级文本里还带着**标题**，中文短文本余弦有个不低的底色，
"标题 + 沾边的前 600 字"往往足以让**正确条目**被召回，只是**分不高**。所以块级买到的是
**多条目竞争时把正确的顶到前面**（0.76 vs 0.54 是决定性差距），而**不是"没有它就查不到"**。
留着它的理由：排序决定的是**孩子拿到哪一条家长口径**，而"top-1 错了"正是阶段① 里最危险的失败
（拿另一件事的说法冒充这件事的）。**但文档里不要再写成"救回盲区"。**
**成本**：块级是**写侧**成本（2 万字最多 64 次嵌入调用，条目级 1 次）；查询侧只多取一次向量。

**另一个实测观察**：家长助手在 `ingest` 时会**自己顺手写 aliases**（把「蜜蜂」「八字舞」写进去），
于是很多问句**在精确路径就被接住**，轮不到语义兜底 → "别名写全"仍是最便宜的那一层，向量是补丁不是替代。

**验证**：新增 `test/kb-p3-chunks.test.ts` **19 例**（确定性 / 短段落合并 / 超长按句切+重叠 / 硬切不吐冗余尾巴 /
去重复块 / 上限 / 整体重建 / 空块跳过 / **删条目连块一起删** / 真实列注册 / ingest 自动切块 /
改 body 重建 / **块向量能排序但门控说了算**）。走真实工具验证了合并路径：问句精确 0 命中 →
语义路径（条目+块合并）找到那份异构文档（答案在尾部块）→ 回话用"候选提示"契约。
KB 受影响面全绿；全量 `npx vitest run` **67 passed / 8 failed（769 passed / 15 failed）**，与前几轮**逐项一致**，零新增失败。

**顺手清的场**：本轮为验证造的两份测试资料（`古代文字.html` 含 25 段重复填充、`家庭活动汇编.html`）与它们的条目
**已删除**；上一轮那两份（`恐龙小知识.html`/`甲骨文小知识.html` 及条目）留着当演示数据。
另外修了一次自己造成的状态污染：验证脚本 publish 后只撤回、没还原 `status`，把一条 draft 变成了 published+parent
（**这正是 publish/withdraw 的设计**：撤回不抹掉"审过"这个事实）——已改回 draft。

## KB P3 阶段④：网页落袋（2026-09-25）

**入口**：`parent_kb_save({ clip: [{ url, topic?, title? }] })`（折进 save）。
抓取 → **自包含 HTML**（图片/样式表内联成 data URL）→ `putMaterial` 落到 `materials/<topic>/<title>.html`
→ 建草稿条目（`body` = 该页纯文本供检索），文件挂上条目。**存成文件，不存 URL**（铁律 2）。

**两段式设计（网络在一边、变换在另一边）**：`fetchPage` 管网络与 SSRF 防线；`sanitizeClippedHtml` 是**纯变换**，
资源靠**注入的 `resolve` 回调**取 → "剥脚本/剥外链/内联图/注入 CSP"整套**完全离线可测**，
而这正是最容易出错、最该被钉住的部分。

「**孩子点不出去**」不是一句话，是清单：`<script>` / `<iframe|object|embed>` / `<form>` /
`<meta http-equiv=refresh>`（**最容易被忽略的导航方式**）/ `<a href>` 降级成 `<span>`（留文字去可点性）/
`on*=` 内联事件 / `<link rel=preload>`；最后叠一层 **CSP `default-src 'none'`**——
**即便上面漏了什么，浏览器也不会发出去**。顺序讲究：**先剥"能发请求"的东西，再内联资源**
（反过来会在剥 `<script>` 之前就替页面把外链图 fetch 了）。

**SSRF 防线**（家长给的任意 URL = 让服务端替他发请求，必须当不可信输入）：协议限 http/https →
主机名字面量筛（localhost/`*.local`/`*.internal`/云元数据，**先判元数据**以给更具体的报文）→
**DNS 解析后逐个 IP 筛**（回环/私网/链路本地含 169.254/唯一本地/CGNAT/保留段，含 IPv4 映射 IPv6）→
**手动跟重定向、每一跳重筛**（只筛首跳等于没筛）→ 流式限量。

**两条与既有约束对齐的决定**：① 产出控制在 1.8MB 内（`putMaterial` 有 **2MB 硬上限**，落袋自己守预算、
超出就不再内联图片并如实警告，**不去改那个已被别的路径依赖的上限**）；
② **绝不覆盖已有资料**——走 `uniqueMaterialRel` 重名加序号（磁盘即真源、没有索引能判断"是不是同一页的新版本"，
**悄悄覆盖等于无声销毁家长已有的字节**）。

**实测（真机）**：`clip https://example.com` → `web/Example 示例页.html`（775B）+ 草稿条目。
落盘核验：**CSP 在**、**无 `<script>`、无 `<a href>`、无任何外链 URL**、出处标记在；保留了自己的内联样式。
助手回话也如实说"脚本/外链/表单已剥掉，孩子点不出去"，并主动指出"example.com 本身没有真实内容，这条给她看没有意义"。
（顺带又见一次**会话记忆**现象：助手列库时念出了我上一轮已删的两条——查库确认确实已不在。）

**验证**：新增 `test/kb-p3-clip.test.ts` **23 例**（SSRF 各类地址 + 相对 URL 归一 / 七类"能发请求"元素的剥离 /
外链降级留文字 / 图片内联与 srcset 清理 / 取不到的图移掉并报警 / 样式内联 / **CSP 注入** / 标题提取与无 head 容错 /
产出上限截断 / 图片数量上限 / slug 与**不覆盖**路径 / 非法 topic 回落 / 工具层：内网与 file:// 报错且**不留半成品**）。
KB 受影响面 **12 文件 / 254 例全绿**；全量 **68 passed / 8 failed（792 passed / 15 failed）** 与前几轮**逐项一致**。
工具块 16731 / 上限 17000（+190，余量 269）。

**P3 四阶段全部完成**（①混合召回 ②入库管道 html/md/txt ③分块 ④网页落袋）。
**仍未做、且需要用户拍板的只剩 PDF 与图片提取**（已写进方案 §5.4.8）：
- **PDF**：仓里没有任何 PDF 解析库；引 `pdfjs-dist` 纯 JS 路径要装依赖 + **打包阶段实测**（§5.5.3 风险 2）。
- **图片**：`app_settings.visionModel` **已经配了**、`parent_read_image` 已在用同一条能力 → **不需要新依赖**，是"接一条现成的线"。
- 两者没做也不影响主流程：`ingest` 遇到会**如实报错并给出路**（口述要点 / 先按"只有资料"挂上），**绝不返回空正文**。

## KB P3 阶段⑤（补做）：图片提取（2026-09-25）

**不引依赖**：走的是一条**现成的线**——`app_settings.visionModel` 已经配了、`parent_read_image` 已在用
`describeImageViaVision`。加前缀标记后进 `body`（`【下面是视觉模型对这张图的描述，不是家长的说法…】`），
**只用来让孩子换个问法也能找到这条**，永远不会成为答案；`summary` 仍然只能家长给。

**为接它做的一处结构调整**：`ingest` 的文本提取原本在**同步**的 `withLib` 里（它保证句柄一定关掉），
而视觉调用是**异步**的 → 把"提取正文"整块**提到开库之前**，与落袋走同一条顺序：**I/O 先做完，再一次性开库写**。
anchor（灌进哪条已有条目）留到库会话里解析，因为那需要读库。

**提块时踩到一个只有运行时才暴露的坑**：`extractIngestText` 返回 `{ text }`，而 `prepared` 里要的是 `{ body }`——
**直接 spread `ex` 会让 body 为空**（`body: undefined` 在 patch 语义下 = "不改动"，于是正文**静默丢失**）。
3 个用例当场红。**这个仓库用不了 `tsc`（TS7 配置问题），这类字段名错位只有测试/真跑抓得住**——别再指望类型检查兜底。

**实测（真机 + 真视觉模型）**：用 Electron `capturePage` 渲染一张带已知文字的 PNG（ffmpeg-static 那个二进制
在本机**直接崩 0xC0000005**，用不了），然后直接调工具 ingest：

## KB P3 阶段⑥：PDF 文本化 + **打包实测**（2026-09-25）

**做法**：`npm install --no-save --no-package-lock pdfjs-dist` 装的（**`server/package.json` 与 lockfile 未被动**，
`git status` 干净）——先把代码路径做完并用真 PDF 实测，把"要不要引依赖"收敛成一个明确的决定，而不是干等。

**四个实测得出的关键点**（都写进 §5.4.8）：
1. **必须用 `legacy` 构建**（`pdfjs-dist/legacy/build/pdf.mjs`）：默认入口在现代构建下打印
   "Please use the legacy build in Node.js environments."，随后直接抛 `hashOriginal.toHex is not a function`。
2. **字体/CMap 要给文件系统路径**（正斜杠、**以 `/` 结尾**）：① 给 `file://` URL 时 Node 的 `fetch` **不支持 file: 协议**
   → 每个标准字体报 "Unable to load font data"（ASCII 能兜住、**中文可能出错**）；② Windows 的 `\` 结尾被拒
   （"must include trailing slash"）。
3. `itemsToText` **用 `hasEOL` 还原换行**——一律拼空格会把标题/正文压成一行，**后续分块也废**。
4. **扫描件（没有文字层）→ 报错，不返回空串**：对家长来说"这是图片型 PDF"和"提取失败"的**下一步完全不同**。

**打包实测（§5.5.3 风险 2 要求的正是这个）**：`npm run build` 成功，24.53MB → **25.87MB（+1.34MB）**，
pdfjs **被打进单文件**；那唯一的 warning 是**既有的** `import.meta` 告警，与 pdfjs 无关。
**但 `standard_fonts/` 与 `cmaps/` 是磁盘目录，esbuild 不会产出**（实测 `dist/` 里没有）→
字体内嵌的 PDF（含多数现代中文 PDF）照常；用**预定义 CMap 的中文 PDF** 或依赖**非内嵌标准字体**的会降级。
**两条出路**：部署时把两个目录与 bundle 一起发，或把 `pdfjs-dist` 标为 esbuild `external` 让它留在 `node_modules`。
（**开发态 `tsx src/index.ts` 两者都不成问题**。）测完**已把原 `dist/server.cjs` 还原**（字节数一致），不擅自改部署产物。

**实测（真机）**：自造一份**能预期内容的多页最小 PDF**（自算 xref 偏移；踩到自己的坑：页面 id 从 3 起会与
`/Pages` 撞 id → 页树自引用，pdfjs 报 "Pages tree contains circular reference"），
`pdfToText` 提取到 `"PAPER DOC 42\nSECOND LINE\n\nPAGE TWO TEXT"`——**就是写进去的字，且分页与换行都对、零告警**；
再走工具 ingest：`guoxue/讲义-测试.pdf` → 草稿条目（`origin=generated`、body 39 字、1 个分块、资产已挂）。

**验证**：新增 `test/kb-p3-pdf.test.ts` **7 例**（纯函数 2 例 + 提取 5 例：内容一致/换行保留/分页分开/页数上限/
**扫描件必须报错并指向截图那条路**/损坏文件给出路/字数上限）。
**可选依赖的处理**：提取那 5 例用 `describe.skipIf` 包着——**没装 pdfjs 时跳过而不是变红**，
并实测过（临时把包移走 → `2 passed | 5 skipped`）。全量 `npx vitest run` 与各轮一致，零新增失败。

**剩下的决定**：把 `pdfjs-dist` 写进 `server/package.json`（一行）+ 选一条数据目录的处理办法。**未擅自加。**
