## 修复：孩子会话时间注入从未生效（learning-guard 扩展没被加载）

- 现象：珊珊会话里 AI 反复把日期搞错（8/13 猜 8/13、8/14~8/15 混乱、8/17 靠运气调 get_date 才对）。用户问「prompt 里包含时间吗」。
- 排查：learning-guard.ts 里的 `before_agent_start` 时间注入（每轮 new Date() 拼「## 当前日期时间」追加到 systemPrompt）**代码早就写了但从未生效**。
- **根因（关键 API 坑）**：SDK 的 `createAgentSession({ extensions: [...] })` **从不读取 `options.extensions`**（该参数被静默忽略）！扩展必须挂在 `DefaultResourceLoader({ extensionFactories: [...] })` 构造参数上，走 `getExtensions()` → `ExtensionRunner` 才会被加载。pi-session.ts 一直把 learningGuardExtension 传给 createAgentSession 的 extensions → 扩展从未加载 → 时间注入 + 越界读写拦截全部失效。
- 端到端实测验证（SDK + 真实孩子目录 + deepseek-v4-flash）：修前 `state.systemPrompt` 31997 字符无「当前日期时间」，AI 答「不调用工具我无法确定日期」；修后含「当前日期时间 现在是 2026-08-18（星期二）…」，AI 直接答「今天是 8月18日，星期二」✅。
- 修复：`electron/lib/pi-session.ts` 孩子会话 loader 加 `extensionFactories: [learningGuardExtension]`；家长模式（getParentSession）同样加上 + 补 `get_date` 工具（原来家长既无时间注入也无 get_date）。
- 验证：构建 ✅；测试 28/29（1 失败为既有 8005 云端注册，无关）。⚠️ 主进程改动需重启 app。
- 教训：SDK 扩展必须走 `extensionFactories`（loader 层），`createAgentSession.extensions` 是死参数；遇到「扩展没生效」先查加载路径。

## 补充：时间注入降精度为「仅日期」（保护 LLM 前缀缓存）

- 上一条修复后注入的是「日期+时分秒」，用户指出：**system prompt 是 LLM 前缀缓存的公共前缀**，每轮注入到秒 → 每轮 system prompt 都变 → 其后全部历史消息每轮都无法命中缓存（DeepSeek context caching 自动生效）→ 首 token 变慢、input 成本全价。
- 修复：`electron/extensions/learning-guard.ts` 只注入「YYYY-MM-DD（星期X）」，不注入时分秒。同一天内 system prompt 完全稳定 → 缓存正常；跨天只变一次。精确时间由 get_date 工具按需提供（工具描述已引导）。
- 验证：构建 ✅；测试 28/29（1 失败为既有 8005 云端注册）。需重启 app 生效。

## 修复：孩子 system prompt 身份错配 + 60 个全局技能噪声

- 背景：孩子会话 system prompt 一直用 SDK 默认 base（「expert coding assistant」身份 + Pi 文档索引），家长有 `systemPromptOverride` 孩子没有。
- **根因 2 更严重**：SDK `packageManager.resolve()` 自动发现并启用 `~/.agents/skills` 全部 60 个全局技能（agent-browser/bilibili-cli/arkcli-*/code-reviewer…），不设 `noSkills` 就全量进 `<available_skills>`。此前 measure-prompt.mjs 直接调 `loadSkills` 绕过了 packageManager，误报「技能段=0」——真实是 60 个噪声 + 2 个教学技能。
- 修复（`electron/lib/pi-session.ts`）：
  1. 新增 `buildChildPrompt(profile)`：孩子专属身份（「你是饺子（🌟），珊珊的学习伙伴，不是编程助手」+ 交流准则），替换 SDK base。
  2. 孩子 loader：`systemPromptOverride: () => buildChildPrompt(profile)` + `noSkills: true` + `additionalSkillPaths: [getSkillsDir()]` → `<available_skills>` 只剩 recording、study-tracker 2 个。
  3. 家长 loader：同样加 `noSkills: true`。
- 验证：`scripts/verify-child-prompt.mjs`（SDK 真实装配 + buildSystemPrompt 模拟拼接）：最终 2,131 字符；无 coding assistant/Pi docs；技能仅 2 个；AGENTS.md/cwd/时间注入自动保留。构建 ✅；测试 28/29（1 失败为既有 8005 云端注册，无关）。主进程改动需重启 app。
- 教训：测 SDK prompt 必须走 `DefaultResourceLoader` 完整链路（packageManager 注入全局 skills/extensions），直接调 loadSkills/buildSystemPrompt 会失真。
