## 1. 为什么按"场景"，而不是按"操作域"

先摆两个家长的真实想法（也是本方案的起点）：

- **要看孩子的学习情况**：「最近考得怎么样、学习结果如何」——他**不会**顺带关心积分。按操作域切，会把积分混进"数据"这一域，一加载就把无关口径塞进上下文。
- **要建一门课**：「建课 → 写教学文案 → 配资料（甚至生成互动页）→ 分配给孩子 → 发现对不上再同步 → 改名」——这是**一件事**。按操作域切，家长会被拆到 `资料` + `档案` 两个技能里，模型还要自己把步骤拼起来，**漏一步就是漏一步**。

| | 按操作域（上一版尝试，已否） | **按场景（本稿）** |
|---|---|---|
| 边界来源 | 我们的**工具台账**（数据/计划/资料/档案/设置） | 家长的**一件事**（"看情况""开一门课""定安排"） |
| 家长做一件事 | 要跨 2–3 个技能，模型负责拼装 | 读**一份**技能就拿到完整流程与口径 |
| 无关内容 | 容易带进不相关的口径（如"看学习情况"带上积分） | 场景内自洽；真的需要时再读第二份 |
| 谁承担复杂度 | 家长（要理解"域"） | 我们（把场景写全、写准） |

> **判据**：如果一句话是家长会**连着说完的一个任务**（哪怕中间跨了好几个工具），就应该是**一个**场景。

## 3. 每个场景长什么样

### 3.1 统一骨架（正文七段，各自 1–2 页内）

1. **触发说法**——家长可能怎么开口（与 description 呼应，给模型做就近匹配）
2. **目标与产出**——这件事办完，家长能拿到什么（叙述 / 落库结果 / 报表 / 清单）
3. **步骤顺序**——哪几步、每步先做什么（**跨工具集也照写**）
4. **每步用哪些工具**、什么顺序、哪些工具**不许用**（如改名不许 upsert）
5. **口径与话术**——怎么解读、怎么讲、怎么报不确定（这一节是重点）
6. **红线**——不可逆先演练复述；认证/账户/密码永不触碰；不写孩子进度字段等
7. **结束条件**——复述"做了什么、影响什么、还差什么"；以及"只说了其中一步就只做那一步"

### 3.2 样例 A：`parent-scene-progress`（家长最高频的一句）

```markdown
---
name: parent-scene-progress
description: 家长想了解孩子最近学得怎么样时用。触发说法：「最近学得怎么样」「这次考了多少、哪几题错了」
  「哪里薄弱、老错什么」「《静夜思》到底会不会」「她昨天到底问了什么」「给我来份周报」。
  产出：一段按主题/知识点聚合的情况叙述，或一份能推到「📊 报表」区的 markdown。
  不含积分与兑换（那是 parent-scene-points）。
metadata:
  covers: D1 D2 D3 D4 D5 D7
---
```

正文要点（不是全文，是骨架里的关键口径）：

- **步骤**：① 先明确"看哪段时间 / 哪个孩子"→ ② 取考核结果（某场逐题 + 每课概要）→ ③ 取知识点档位与学习结果 → ④ 取错题本概览 → ⑤ 需要细节时读逐字稿 → ⑥ 组织成一段叙述（家长要报表时用 `parent_display_report`）。
- **口径**：**先整体（得分/范围）→ 再讲错在哪 → 区分"没学过"与"学过但错"**；档位说 `solid/partial/weak`；**"没分析过" ≠ "学得差"**（没数据要如实说没数据）；错题按知识点聚合，不是罗列明细；进度取"最近学习时间"、掌握取"最近一次得分率"，**按主题聚合、不整表罗列**。
- **红线**：逐字稿只读、只限自己名下孩子、**概括要点不大段复述**；**不许替孩子标 mastered**；**不提积分**（家长问了再读 `parent-scene-points`）。
- **结束**：一句话复述"看了哪段时间、结论是什么、哪里数据不足"。

### 3.3 样例 B：`parent-scene-course`（家长的一件"工程"）

```markdown
---
name: parent-scene-course
description: 家长要开一门课、改一门课、给课配资料，或"孩子的课对不上"时用。触发说法：
  「我想开一门国学」「这主题下加三课」「这门课用这份资料」「给这课做个互动练习页」
  「让孩子能学这门课」「把《学而篇》改叫《论语·学而》」「孩子那边怎么找不到这门课」。
  产出：主题/课程结构 + 教学文案·资料路径·考核要点落库，必要时分配并同步到孩子端。
  家长只说了其中一步时，就只做那一步，不必走完整条线。
metadata:
  covers: B1 B2 B3 B4 B5 B6 C5 C6
  工序: craft-interactive-page
---
```

正文步骤（**跨工具集的一条线，正是"按场景"的意义**）：

1. **先核对现在有什么**（`parent_library_topics` / `parent_library_courses`）——不许凭记忆建重名。
2. **落结构**：主题（目录名 / 教学方法 / 考核方法）→ 课程（`(topic,title)` 联合主键 upsert）；**进度字段不手写**。
3. **写教学三件套**：讲什么 / 用什么资料（`html_path`）/ 考什么。**`html_path` 必须与资料真源里真实存在的文件对上**（当前工具不校验 → 先列同主题下候选让家长确认）。
4. **造 / 放资料**：`parent_build_material`（拉起编程 agent；**没配编程模型会明确报错，要先告知并指路**）／界面上传／`parent_put_material`（覆盖前先读，防误盖手改版）。
5. **让孩子能学**：**分配是界面动作，工具不代分配**；再用 `parent_sync_courses_to_child`（只到已分配主题、幂等、**跳过了什么要如实转述**）。
6. **改名只走 `parent_rename_course`**（绝不用 upsert）；改完提醒"旧计划里的旧课名要人工核对"。
7. **收尾复述**：这门课现在有什么、孩子那边能看到什么、还差什么。

## 4. 承载机制：核实过的技术事实（决定方案的形态）

| 动作 | 会话 / 历史 | 系统提示与前缀缓存 | 结论 |
|---|---|---|---|
| **加载一个场景技能**（读 `SKILL.md`） | 不动 | **不失效**（技能正文是以"工具结果"追加到消息**尾部**，缓存前缀原样） | **这是本方案的基础**：会话内随便读，只按新文本付一次钱 |
| 会话内切工具集 | 不动 | **失效一次**（工具数组与系统提示都在消息**之前**，改头＝整条前缀作废） | **所以本方案不切工具集**（决定 3） |
| 重建会话 | 清空 | 全废 | 与场景无关，只发生在 `/reset` 或跨天自动新会话 |

**其余四条已核实的事实**（写在文档里，避免将来重复踩）：

1. **内核（`pi-coding-agent` 0.84.1）本来就支持 Agent Skills**（`SKILL.md` + 渐进披露 + `<available_skills>` 索引），但服务端**默认关着**（`packages/agent-core/src/sessions.ts` 里 `noSkills ?? true`）。
2. **即使打开也读不到**：SDK 索引里给的是**绝对路径** `<location>`，而我们的 `read` 工具**拒绝绝对路径**、`learning-guard` 又把 FS 路径限制在会话 cwd。⇒ 必须**自建 `load_skill(name)`**（受控目录按名读），或自建索引。
3. **若改用 SDK 默认发现目录，有红线级风险**：它会扫 `~/.pi/agent/skills`、`~/.agents/skills`，以及 **cwd 及其所有祖先目录**的 `.pi/skills`（`package-manager.js`），而 cwd 是**模型自己可写**的地方 ⇒ 模型可以给自己写指令，跨天新会话生效。⇒ 保持 `noSkills` 关闭，只用显式受控路径。
4. **`read` 必须常驻**：SDK 只在 `read` 处于激活工具时才注入技能索引。若将来真去缩工具集，**不能把 `read` 缩掉**。
5. **真要缩小工具集，正确位置是"会话创建时按会话类型定"**（现在 `parent` / `parent-content` 已经是这个思路），而不是会话内按场景切。

## 5. 常驻层（L0）与索引

常驻层**每轮都在**，必须压到最短。内容四样：① 身份 + 安全红线（认证/账户/密码永不触碰；不可逆动作先演练复述）；② 今天几号；③ **库表速查**（模型得先知道去哪找，这部分不能按需）；④ **场景索引**。

**索引写法**（一行一个场景，共 8 行 + 2 句说明）：

```
- 了解孩子最近学得怎么样（考核、掌握、错题、逐字稿、周报）→ parent-scene-progress
- 开课 / 改课 / 配资料 / 同步到孩子端 → parent-scene-course
- 排课、排生活计划、排考核、长期固定项（每周…） → parent-scene-plan
- 到点自动执行的任务与提醒（每天早上…） → parent-scene-automation
- 资料库盘点 / 查重 / 整理 / 删除 / 读附件 → parent-scene-materials
- 加孩子、改档案与人设 → parent-scene-child
- 积分怎么算、兑换审批 → parent-scene-points
- 改系统设置（只解释、不改） → parent-scene-config
以上都不像时，按常驻工作原则正常答；一句话里跨两件事时，连续读两份即可。
"每天/每周"这类重复说法在两个场景里都有说明；拿不准用哪个时，先问一句"是要排进日程，还是要到点自动做"。
```

## 6. 工序技能（被引用，不主动进）

有些做法会被**多个场景**用到，别复制多份：

| 工序技能 | 内容 | 被谁引用 |
|---|---|---|
| `craft-interactive-page` | 造互动页/绘本的 `path` 语法、要交代清楚内容与结构、**没配编程模型怎么办** | `course`（主）、`materials`（"给这份资料做个互动页"） |
| `craft-report` | 报表的 markdown 结构、必须用刚查到的真实数据 | `progress`（周报）、`points`（积分报告） |

规则：**工序技能不写进常驻索引**（模型不主动进），只在场景技能正文里点名"这一步按 `craft-*` 做"。

### 6.1 "口径只写一处"的**唯一例外**：重复规则（2026-09-25 决定）

**重复规则**（"每天/每周"到底怎么落、生效区间、停用与删除的区别）要在 **`parent-scene-plan` 与 `parent-scene-automation` 两处都写**——因为家长在这两件事里都会说"每天/每周"，而且**两处的落库机制本来就不同**：

| | `parent-scene-plan`（排进日程） | `parent-scene-automation`（到点执行） |
|---|---|---|
| 家长说法 | 「每周一到周五都练字」 | 「每天早上 6 点查天气并播报」「每天提醒她做眼保健操」 |
| 怎么落 | `parent_recurrence_*` → **系统每天展开成当天的计划行** | 自然语言指令**写在任务里**，到点由执行会话跑 |
| 重复的载体 | 规则（可 `_list` / `_update` 改、停用≠删除） | 指令文本本身（改了就是改任务；失败不重试） |

⇒ 这是刻意接受的一处重复，**必须配两条纪律，否则一定漂移**：

1. **同源**：那段重复语义（`daily` / `weekly` 的含义、生效区间、**停用 ≠ 删除**）**逐字同源**——要么同一段文本复制，要么拼装时注入同一片段，**不许两处各写一版**；
2. **一致性验收**：样本里加一条（§9 第 18 条）——分别用"每周一到周五都练字"和"每天提醒她做眼保健操"问"这个每天/每周是怎么落的、以后怎么停"，**两处解释必须一致**，且都要说清分工（排进日程 → 计划重复；到点自动做 → 定时任务）。

## 7. 家长自定义层：按**场景**同名覆盖 ——✅ 已落地（P5）

家长端原来**只有写死的 ①，没有可改层**；本方案顺手把它补上，方式是**复用现成机制**，不新建：

- 家长改写某个场景的口径 → 存进现有 `agents.sqlite`（`scope="parent"`，**库内键 `skill:<家长id>:<技能名>`**）→ 拼装时 **DB 优先、文件兜底**；**50 版历史与回退直接复用**现有接口（设置 →「场景口径」）。
- **为什么覆盖粒度是"场景"而不是"域"**：家长的偏好本身是场景化的——典型正是「**看学习情况时别提分数、别提排名，只说掌握情况**」「积分扣成负的时候别用负向词」。按"数据域"覆盖会太粗，一改就把"考得怎么样"也改掉了。
- **不可覆盖**：安全红线（认证/账户/密码、删孩子、不可逆动作的确认流程）、工具白名单、步骤顺序中的硬约束（如"改名不许 upsert"）。这些一律来自代码——三道闸：① 铁律在**常驻层**；② 覆盖版生效时 `load_skill` **代码追加「不可覆盖条款」**；③ 保存时**红线关键词校验**当场 400。
- **⚠️ 一处必须记住的实现细节（P5 修正）**：`agents.sqlite` 是**服务端全局一个文件**（家长隔离全靠 `scope='parent' + ref=<parentId>` 这套约定），所以库内键**必须带家长 id**——P2.4 起初写成 `ref="skill:<name>"`，多家长会**串口径**。现已改为 `skill:<家长id>:<技能名>`，并加了跨家长隔离测试。
- **生效时机**：技能正文在会话里 `load_skill` 读过一次就固定了 → **改完要开新会话**（界面里已写明）。

## 8. 硬依赖：通用数据 API 退场（先补工具，才能退）——✅ 已执行（P4 → P6）

`progress` 与 `points` 两个场景原来是**靠通用通道直读表行**（`parent_db_read`）撑着的，而通用 API 已决定不再使用（台账 §3.2）。**顺序不能颠倒**：

| 先补（场景专用读工具） | 才能退掉 | 否则 | 状态 |
|---|---|---|---|
| `parent_child_exam_report`（考核逐题 + 每课概要） | `parent_db_read` 在 D1 的用法 | 「这次考得怎么样」**断供** | ✅ 已就位 |
| `parent_child_mastery_report`（知识点档位 + 学习结果） | D5（D2 进度可退回 `parent_library_topics`） | 「哪里薄弱」**断供** | ✅ 已就位（并承接 D3 错题本） |
| `parent_child_points_report`（积分与结算 + 兑换） | F3 / F2 | 「她这分怎么算的」**断供**；兑换改走界面 | ✅ 已就位（读；**发放仍无对话入口**） |
| 错题本（D3，已有口径） | — | 需一段专用读工具，或并入掌握报告 | ✅ **并入掌握报告** |

⇒ **已执行（2026-09-25）**：三件落地（`ISSUE-144` §3.5）后，家长拍板**当场拆桥**（口径：**以后场景缺少工具就给它补一把专用工具**），**P6 已把通用通道整组退场并删净代码**——四把工具（含 `define_namespace`）、`parent-data` 会话、常驻兜底段、两库元数据块、侧栏入口与视图全删（执行清单见台账 §3.2 / 实施方案 §3 P6）。**这三件也是 `progress` / `points` 两个场景技能能"讲得清"的前提**——口径写在技能与专用工具里（孩子端 `ISSUE-142` 已验证）。
