# 阿里云 SSECP 语音评测：返回结果里到底有什么

> 调研日期：2026-10-19 ｜ 对应代码：`server/src/assessment/providers/aliyun-ssecp.ts`（provider = `aliyun-ssecp`）
> 结论先放前面：**服务端一直都在返回逐字/逐词的分数与对错标记，颜色消失不是接口退化了，而是我们自己的映射 + 前端渲染把这块丢了。**

---

## 1. 先确认是哪个"阿里云服务"

我们接的不是「智能语音交互 NLS」，而是 **阿里云智能科教内容生成平台（SSECP，产品页 aliyun.com/product/ssecp）**，底层引擎是声希（singsound）。本文所有字段都出自 SSECP 文档；NLS 的语音评测是另一套接口和字段，不要混用：

| 项 | 值 |
| --- | --- |
| 鉴权 | `POST http://api.cloud.ssapi.cn:8080/auth/authorize`（MD5 签名）→ `warrant_id` |
| 评测 | `POST https://api.cloud.ssapi.cn/{coreType}?appkey&connect_id&request_id&warrant_id`，multipart：`text`(JSON) + `audio`(wav) |
| 我们的题型选择 | 中文（含汉字）→ `cn.pred.score`（篇章跟读）；英文 → `en.sent.score`（句子） |
| 支持的题型 | 中文 6 种 + 英文 15 种，共 21 种 `coreType` |

中文（6）：`cn.raw.score`(拼音)、`cn.word.score`(单字/词/成语)、`cn.pred.score`(篇章)、`cn.pcha.score`(选读)、`cn.recite.score`(背诵)、`cn.poet.score`(诗歌)。

英文（15）：`en.word.score`、`en.sent.score`、`en.pred.score`(段落)、`en.alpha.score`(音标)、`en.word_kid.score`(儿童单词)、`en.sent_kid.score`(儿童句子)、`en.nsp.score`(自然拼读)、`en.mpd.score`(单词纠错)、`en.choc.score`(单项选择)、`en.pche.score`(扩展选择)、`en.pcha.score`(选读)、`en.pqan.score`(问答题)、`en.pict.score`(看图说话)、`en.retell.score`(故事复述)、`en.recite.score`(背诵)。

## 2. 返回 JSON 的完整层级

```
{
  tokenId, recordId, applicationId, refText, eof, dtLastResponse,
  audioUrl,                       // 需请求时 attachAudioUrl=1
  cloud_platform.origin_audio_length,
  params: { app, audio, request },// 原样回显请求
  result: {
    overall, pron, accuracy, integrity, tone,
    fluency,                      // 中文篇章/段落 = 数字；英文句子 = {overall,pause,speed}
    rhythm: {overall,sense,stress,tone},  // 仅英文句子类
    wavetime, rank, precision, res, version,
    systime, pretime, delaytime, forceout,
    info: { snr, clip, volume, tipId },
    details: [ ... ],             // ★ 逐句 / 逐字 / 逐词，颜色标注就用它
    realtime_details: [ ... ],    // 仅 feedback=1（实时反馈）
    statics: [ ... ],             // 仅英文：音素平均分统计
    result_compare: { ... }       // 仅 enableCompareAudio+std_audio_url：音频对比曲线
  }
}
```

### 2.1 维度分

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `overall` | 综合总分 | 文档标"内部参数"，部分题型仍给 |
| `pron` / `accuracy` | 发音分（两者同值） | 准确度 |
| `integrity` | 完整度（有没有读全） | 背诵题抓漏句主要靠它 |
| `fluency` | 流利度 | 英文是对象，中文篇章是数字 |
| `rhythm` | 韵律（重音/升降调/意群） | 仅英文句子 |
| `tone` | 声调分 | 多为"保留备用" |
| `wavetime` | 音频时长 ms | |
| `info.snr/clip/volume` | 信噪比 / 截幅(0~1) / 音量 | |
| `info.tipId` | 音频质量结论 | 见 §4 |
| `systime/pretime/delaytime` | 服务端耗时 | 排查性能用 |

### 2.2 `details` 的三种形状（最容易踩的坑）

**A. 中文篇章 `cn.pred.score`（我们当前用的）—— 两层：句子 → 字**

```json
"details": [{
  "text": "山不在高，", "score": 64,
  "fluency": { "pause": 0, "overall": 97, "speed": 1 },
  "snt_details": [
    { "chn_char": "高", "char": "gao", "tone": 1, "tonescore": 99,
      "score": 34, "start": 1680, "end": 2020, "dur": 340 },
    { "chn_char": "惟", "char": "wei", "tone": 2, "tonescore": 0,
      "score": 0, "start": 0, "end": 0, "dur": 0, "dp_type": 1 }
  ]
}]
```

**B. 中文背诵 `cn.recite.score` / 单字 `cn.word.score` —— 一层平铺**

```json
"details": [{ "chn_char": "疑", "char": "ni", "tone": 3, "score": 0,
              "dp_type": 1, "start": 0, "end": 0, "dur": 0 }]
```
单字题型还多：`pron`、`phn`（不带声调发音分）、`overall`、`tonescore`、`confidence[5]`（轻声/1/2/3/4 声概率）、`phone[]`（声韵母得分，需 `outputPhones`）。

**C. 英文句子/单词/儿童句子 `en.sent*.score` / `en.word*.score` —— 词 → 音素**

```json
"details": [{
  "char": "basketball", "score": 72, "start": 1820, "end": 2580, "dur": 760,
  "fluency": 96, "dp_type": 2, "is_pause": 1, "accent": "en",
  "stressref": 0, "stressscore": 0, "toneref": 0, "tonescore": 0,
  "senseref": 0, "sensescore": 1, "liaisonref": 0, "liaisonscore": 0,
  "fake_pron": 0,
  "phone": [{ "char": "b", "ph2alpha": "b", "phid": "1",
              "score": 98, "start": 1820, "end": 1900, "pherr": 0 }]
}]
```

**D. 英文段落 `en.pred.score` —— 句 → 词，但只有 `{char, score}`**，没有 `dp_type`、没有音素、没有时间戳。要细粒度反馈别选它。

> 关键：**A 和 B 的层级不同**。读 `details[i].chn_char` 的渲染器遇到 A 会全部拿不到 → 页面只剩原文。这是"以前有颜色、换了题型后没了"最典型的原因。

## 3. 判对错/标颜色可直接用的字段

| 用途 | 字段 | 规则 |
| --- | --- | --- |
| 漏读 / 多读 | `dp_type` | `0` 正常（通常不输出该字段）、`1` 漏读/未读、`2` 重读、`3` 注释字不参与评分（智聆的 `MatchTag=3` 是"错读"，渲染层按 provider 区分） |
| 字/词发音好坏 | `score` | 0–100 |
| 声调对不对 | `tonescore`（+ `tone` 0–4） | 0–100；`score` 高但 `tonescore` 低 = 声调问题 |
| 句中停顿 | `is_pause: 1` | 英文词级、中文篇章字级都有 |
| 句子得分 | `details[i].score` / `fluency.pause` | 断句维度 |
| 音素级错误 | `phone[].score` / `phone[].pherr` | 英文，需 `outputPhones=1` + `phdet=1` |
| 音频质量 | `info.tipId` | 见 §4 |
| 回放 | `audioUrl` | 需 `attachAudioUrl=1`；云端只留约 20 天 |

**`dp_type` 是"读错/漏读"的权威标记**，`score` 只是分数——颜色若只按分数，会把"漏读 0 分"和"读得差 0 分"混为一谈。

## 4. 请求参数能"解锁"的额外信息

我们目前只传了 `rank/precision/refText/coreType`，以下都没开：

| 参数 | 作用 |
| --- | --- |
| `outputPhones=1\|2` | 返回声韵母/音素得分（1=需映射的内部音素，2=实际音标） |
| `phdet=1` | 音素检错（`pherr`/`phid`/`ph2alpha`） |
| `syldet=1` | 音节检错 |
| `feedback=1` | 逐帧 `realtime_details`（实时读到哪个字、`dp_type` 实时变化） |
| `attachAudioUrl=1` | 返回 `audioUrl` |
| `symbol=1` | 返回结果保留标点（默认 0 会去标点） |
| `typeThres` | 打分松紧：1 严格 / 2 宽松 / 3 非常严格 / 4 非常宽松 |
| `auto_rhythm=1` | 连读检测 |
| `enableCompareAudio=1` + `std_audio_url` | 音频对比：`result_compare`（语速/音调/音量曲线 + 相关度） |
| `use_cws=1` | 分词（多音字/数字更准） |

`tipId` 对照（可直接做"录音没录好"的提示）：

| tipId | 含义 | 建议文案 |
| --- | --- | --- |
| 10000 | 音频长度为 0 | 没录到声音 |
| 10004 | 音量偏低 | 离麦克风远/声音小 |
| 10005 | 音频截幅（太近） | 离麦克风太近 |
| 10006 | 信噪比低（环境吵） | 换安静环境 |
| 10008 | 模拟信号截幅 | 调小音量 |

## 5. 为什么现在"只显示原文、一个颜色"

### 5.1 数据没丢，链路上三段都在

1. `aliyun-ssecp.ts:144` `parseSsecpResult()` 已经把 `details → snt_details` 映射成 `words[{word,score,dpType}]`，并且 `raw` 原样带回。
2. `toSpeechAssessment()` 把 `words` + `raw` 塞进 `SpeechAssessment`。
3. `POST /assessment/assess` 原样返回；提交考核时 `speech` 整包写进 `speech_assessments.detail_json`。

也就是说：**历史评测结果里同样存着逐字分数，可以"补渲染"旧成绩，不用重新评测。**

### 5.2 真正丢信息的是两处

| 位置 | 问题 |
| --- | --- |
| `parseSsecpResult` | 只取 `chn_char / score / dp_type`，丢掉了 `tone / tonescore / phone / is_pause / 句子 text / details[i].score / fluency` |
| 前端 | 全仓没有任何组件把 `speech.words` 渲染出来。报告页只渲染 `原文：{q.refText}`（`ExamView.tsx:733`），历史成绩页同理；`AssessmentSettings` 只数了 `words.length` |

所以不是阿里云不返回了，是**我们从来没把这块画出来 / 或者画它的代码在某次重构里没了**。

### 5.3 若"以前确实有颜色"，可能是这几种

> 说明：本仓库 git 历史（含初版考核 `e438299`）里没有找到任何按字上色的组件，报告页从初版起就只显示 `原文`。所以"以前有"更可能来自更早的产品版本、另一条渲染链路，或当时看的是控制台/厂商 demo。

1. **题型从平铺换成嵌套**：`cn.recite.score` / `cn.word.score` 的 `details[]` 是平铺单字，`cn.pred.score` 是 `details[].snt_details[]`。读 `details[].chn_char` 的旧渲染器遇到新结构会全部取空 → 只剩原文。
2. **provider 切换**：腾讯智聆用 `MatchTag`（正常/漏读/多读/错读），阿里用 `dp_type`；颜色规则若写死在某一家上，换 provider 就失效。
3. **只存了维度分**：早期若只把 `overall/pron/...` 落库、没存 `raw/words`，事后想补颜色也无数据可用（现在 `detail_json` 存了整包，没这个问题）。

## 6. 要恢复颜色，最小改法（2026-10-19 已落地，见 §8）

1. **服务端**：`WordScore` 增加 `toneScore`、`isPause`、`sentenceIndex`、`start/end`；中文按 `details[].snt_details[]` 展开，英文直接 `details[]`。同时在 `toSpeechAssessment` 里补 `sentences`。
2. **前端**：新增 `SpeechText` 组件，输入 `refText + words`，输出逐字 `<span>`：
   - `dpType===1` → 灰 + 删除线（漏读）
   - `dpType===2` → 橙色波浪下划线（重读）
   - `dpType===3` → 灰（注释字，不评分）
   - 否则按 `score`：`<60` 红、`60–79` 橙、`≥80` 绿；`tonescore<60 && score≥80` → 黄（声调问题）
   - `isPause` → 字后加 `⏸`
3. **对齐坑**：
   - `chn_char` 可能带标点（"高，"），且 `symbol` 默认 0 时会去标点——先按字符剥离标点再与 `refText` 对齐；
   - `refText` 里的多音字标注（`数(shu3)` / `数<z:shu3>`）要先剔除再显示；
   - `details` 里可能包含未读句子（整句 0 分），不要当"额外文本"渲染。
4. **阈值可配**：颜色分档放配置里，别写死；儿童场景 60 分红线偏严，建议按家长端"通过线"联动。

## 8. 落地记录（2026-10-19）

### 8.1 服务端（`server/src/assessment/`）

- `types.ts`：`WordScore` 增加 `tone / toneScore / isPause / sentenceIndex / startMs / endMs`；新增 `sentences[]`、`audioQuality`。
- `providers/aliyun-ssecp.ts`：
  - `parseSsecpResult` 改为**按节点是否带 `snt_details` 自动判别嵌套/平铺**（不再只按 coreType 前缀分支，换题型不会取空）；
  - 中文映射 `chn_char / char / tone / tonescore / is_pause / start / end`，英文映射 `char / phone[{char,score,start,end}]`；
  - 英文的 `tonescore` 是"升降调 0/1"，**不**映射到声调分；
  - 带回 `result.info`（tipId/snr/clip/volume）。
- `toSpeechAssessment`：逐字字段与 `sentences/audioQuality` 透传给客户端。
- `GET /api/v1/exam/attempts/:childId`：从 `speech_assessments.detail_json` 回填每题 `speech`（只回展示子集，剔除 `raw`，避免列表体积膨胀）；旧库无该表时静默降级。
- `detail_json` 里本来就存整包 `speech`，所以**历史成绩也能补出逐字颜色，不用重考**。

### 8.2 客户端

- `src/lib/speech-text.ts`（纯逻辑，可单测）：原文分词（中文逐字/英文逐词/标点空白不消耗 words）、`dp_type` 与分数分档、hover 文案、汇总统计；`dp_type=3` 按 provider 区分（声希=注释字，智聆=错读）。
- `src/components/SpeechText.tsx`：逐字着色 + 图例 + 漏读/重读标记 + `⏸` 停顿标记 + 点字回放（按 `start/end` 切片）+ 录音质量提示（tipId）。
- 接入点：
  - 考核报告「逐题评估」：口语题在评语下方展示逐字结果；
  - 历史成绩详情（孩子端 ExamView / 家长端 ChildExamPlans）：有 `speech.words` 时用逐字视图替代纯文本「原文」；
  - 设置 → 发音评测 →「测试评测」：试评 `hello` 后直接看逐词颜色。
- 测试：`test/speech-text.test.ts`（解析两种 details 形状 + 着色分档/对齐），与 `test/issue183-dimension-mean.test.ts` 一并通过。

### 8.3 `typeThres` 现状

**已实现为家长可调项**（2026-10-19，server 0.5.40）：`assessment_config.typeThres`，家长端「设置 → 发音评测 → 打分松紧」五档（0 默认 / 1 严格 / 2 宽松 / 3 非常严格 / 4 非常宽松）；0 时不传参、保持引擎默认，1-4 才写进 SSECP 的 `request.typeThres`。只对阿里 SSECP 生效（腾讯智聆无此参数），按家长维度加密落库、多端同步。
