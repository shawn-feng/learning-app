# 学习主题打包导出/导入 —— 设计方案

> 2026-09-25。需求：**学习主题设计好后，一键打包成一个文件；在另一套「学习伙伴」部署上选这个文件一键导入**，得到一个与手工建出完全等价、可分配给孩子的主题。
>
> **实施状态（2026-09-26）**：P0 已实施并**部署 201（learning-server 0.5.12）**——服务端 `server/src/routes/topic-package.ts`（预览/导出/导入）+ Electron（`electron/lib/topic-package.ts` + IPC/preload）+ Web shim（`domains/parent.ts` 同名三方法）+ 课程管理页入口（卡片「打包导出」/顶部「导入主题」）+ `test/topic-package.test.ts`（16 例）+ 双实例 HTTP 冒烟通过（`tmp/topic-smoke.sh`）+ 千字文真实数据（30 课/60 文件）预览验证通过。**377MB 整包**（30 段视频）从 201 真实导出+跨机导入实测通过（无上限实证）。
>
> 已拍板（2026-09-25 与用户确认）：
> 1. **目标端** = 另一套学习伙伴部署（另一台服务器/另一个家庭），不是别的产品；
> 2. **包内容** = 主题+课程结构、题库+知识点 **必含**；教学资料文件 **可选**——导出时列出资料文件清单，按类型批量勾选或单文件勾选，**默认不打包**；
> 3. **传输** = 导出成文件人工传（微信/U盘），对端「导入主题」选文件；云端中转不做（协议不排斥，后加不影响格式）；
> 4. **知识库条目（kb_entries 五表）不进包**。

---

## 1. 范围：什么进包、什么不进

一个「设计好的主题」的内容分散在服务端 4 处（客户端是瘦客户端，数据全在 learning-server）：

### 进包

| 内容 | 来源 | 说明 |
|---|---|---|
| 主题行 | 家长库 `topics` | `name / topic_key / method / assess_method / progress / rules_json`（`progress` 是家长手写的教学进度备注，属内容，进） |
| 课程行 | 家长库 `courses`（`topic = topic_key`） | 全部内容列：`uuid / title / sort_order / material / send_material / tags / lesson_method / html_path / teaching_copy / assess_rubric` |
| 考核内容 | 家长库 `question_bank / knowledge_points / course_knowledge_questions` | 按 `courses.uuid` 挂靠，原样进包（含题级 `behavior/note/knowledge_summary/options`） |
| 资料文件（**可选勾选**） | `workspaces/<parentId>/materials/<topicKey>/` 前缀下全部文件 | 读取走既有 `resolveMaterialFile`（新根优先、旧根兜底），html 互动页/视频/图片/音频/文档 |

### 不进包（及理由）

| 内容 | 理由 |
|---|---|
| 孩子库一切（分配关系、进度、掌握度、错题本） | 「使用」数据不属于主题；导入端重新走既有「分配给孩子」流程 |
| `topics.method_spec` | 按孩子区分的考核 spec（系统域），由导入端考核设置流程生成 |
| 知识库条目 `kb_entries` 等五表 | 本次拍板不含 |
| `tags` 表定义、Tier2 `entities`、向量旁表 | 家长级附属/派生数据，导入端按需重建 |

## 2. 包格式

- 文件名：`<主题名>-<YYYYMMDD>.ltpkg`；**本质是标准 zip**（手头排查可改后缀解开）。
- 布局：

```
manifest.json              ← 全部结构化数据 + 文件清单
files/<topicKey>/...       ← 勾选的资料文件，保持原有相对路径
```

- `manifest.json`（`schema_version: 1`）：

```jsonc
{
  "kind": "learning-topic-package",
  "schema_version": 1,
  "created_at": "2026-09-25T12:00:00.000Z",
  "source": { "client_version": "0.1.20", "server_version": "0.5.x" },
  "topic": { "name": "论语", "topic_key": "lunyu", "method": "...", "assess_method": "...", "progress": "...", "rules_json": "{}" },
  "courses": [ /* uuid/title/sort_order/material/send_material/tags/lesson_method/html_path/teaching_copy/assess_rubric */ ],
  "question_bank": [ /* id/stem/answer/scoring/point_max/behavior/note/knowledge_summary/options */ ],
  "knowledge_points": [ /* id/course_uuid/name/detail/seq */ ],
  "course_knowledge_questions": [ /* course_id(=课程uuid)/knowledge_point_id/question_id/seq/overview */ ],
  "files": [ { "path": "lunyu/lesson-1.html", "size": 12345, "sha256": "…" } ]
}
```

- **兼容规则**：导入端拒收 `kind` 不符或 `schema_version` 主版本更高的包（低版本可导）。
- `files[].path` 与 `courses.html_path / material` 引用同一套 `topic/file` 相对路径语法；sha256 供导入端可选校验。

## 3. 导出流程

### UI（家长中心 → 课程管理）

- `CourseManager.tsx` 主题卡片按钮组加第 5 个卡片按钮「打包导出」（lucide `Package` 系图标，与现有 教学方法/考核方法/课程详情/学习资料管理 并列）。
- 新组件 `TopicExportDialog.tsx`：
  1. 打开即请求**预览**（主题信息 + 课程数/知识点数/题目数 + 资料文件清单 `path/type/size/被几门课引用`）；
  2. 「是否打包资料文件？」默认**否**——直接点「导出」即纯数据包；
  3. 选「是」展开文件清单：**按类型分组**（网页/图片/音频/视频/文档/其他），组头全选框可批量勾选本类型，文件行单独勾选，显示单文件大小并实时合计总体积；
  4. 「导出」→ 服务端生成 zip → Electron `dialog.showSaveDialog` 落盘 / Web 走浏览器下载。

### 服务端（新文件 `server/src/routes/topic-package.ts`）

- `GET /api/v1/parent-lib/export-topic/:topicKey/preview` → 预览 JSON（文件列举复用 `walkFilesRecursive` + `inferType`，refCount 数 `courses.material/html_path` 前缀命中）。
- `POST /api/v1/parent-lib/export-topic`，body `{ topic_key, files: string[] }` → `application/zip`。
  - 收集 4 张表数据 → `zipPack`（`backup.ts` 现成零依赖实现，导出复用）；
  - **体积策略（2026-09-26 用户拍板）**：**不设上限**——千字文级别（377MB 整包）实测导出/导入通过；导入端 multipart `fileSize: Infinity`。zip 打包/解包均为内存操作，超大数据包的流式优化留待实际遇到瓶颈再做。
- 鉴权：沿用现有家长 auth，只读本家长的家长库与工作区。

## 4. 导入流程

### UI

- `CourseManager.tsx` 顶部「导入主题」按钮（与「新建主题」并列）→ 新组件 `TopicImportDialog.tsx`：选文件（Electron `dialog.showOpenDialog` / Web `<input type=file>`）→ 上传 → 展示**导入报告**。

### 服务端 `POST /api/v1/parent-lib/import-topic`（multipart，复用已配的 200MB 上限）

1. `zipUnpack`（`backup.ts` 现成）→ 校验 `manifest.json`（kind / schema_version / 必填字段）；
2. **冲突处理（实施定稿，三分支身份裁决）**：
   - 目标库无同名主题 → 直接导入；
   - **同名且同 topic_key** → 视为同一主题的重复导入，**幂等刷新**（`INSERT OR REPLACE` 主题/课程，`INSERT OR IGNORE` 题库/知识点/挂载），报告 `refreshed: true`；
   - **同名但不同 topic_key** → **自动重命名**（`name` 加 `" (2)"`、`topic_key` 加 `-2`），并同步改写 `courses.topic`、`html_path / material` 的目录前缀、`files/` 落盘目录；报告 `renamed: true`；
   - `courses.uuid` 碰撞（跨库概率≈0）→ 重新生成 uuid 并重映射 `knowledge_points.course_uuid / course_knowledge_questions.course_id`。
3. **写库**（单事务）：`topics / courses / question_bank / knowledge_points / course_knowledge_questions`；
4. **落文件**：`files/` 内条目写到 materials **新根** `<新topicKey>/` 下；
5. **防穿越**：zip 条目路径 normalize 后必须落在目标目录内（拒 `..`/绝对路径/盘符）；以 `manifest.files` 为白名单，包内多余条目忽略；
6. 返回报告：`{ topic, renamed?: {from,to}, courses: n, knowledge_points: n, questions: n, files: n, missing_files: [...] }`——`missing_files` = 课程引用了但未随包的 `html_path / material` 清单。

### 导入后的状态

主题为**未分配**状态；家长到孩子详情走既有「分配给孩子」（`ChildTopicsModal → parent:allocate`）即可，资料已随包的场景分配即完全可用。

## 5. 不带资料的表现（默认路径）

- 导入报告明示「N 门课缺资料文件」及清单；
- 上课端已有兜底（正文为空的 html 跳过、媒体缺失有提示）；
- 对话框引导文案：「可在导入端用家长 agent 重新生成资料，或请原作者导出一个带资料的包」。

## 7. 测试与验收

**单测**（`test/topic-package.test.ts`）
1. 包构建：4 张表数据完整、manifest 字段齐全、文件清单与实际一致；
2. 包解析：坏包/错 kind/高 schema_version 拒收；路径穿越（`../`、绝对路径、盘符）拒收；白名单外条目忽略；
3. 冲突：同名 topic 自动重命名后 `courses.topic / html_path / material / 落盘目录` 四处前缀同步改写；uuid 碰撞重映射；
4. 幂等：同包重导，行数不变；
5. 缺资料：`missing_files` 清单正确。

**端到端手测清单**
- 导出（默认不带 / 全选带 / 部分勾选带）→ 微信传文件 → 另一实例导入 → 报告核对 → 分配给孩子 → 孩子端上课：课程可见、资料页可开（带了的部分）、考核出题可用（题库随包）→ 家长端可再编辑/再分配。

## 8. 明确不做（本期）

- 云端中转、应用内分享；
- 增量/差异更新包；
- 包加密或签名（内网/熟人分享场景，manifest 有 sha256 校验即可）；
- 知识库条目、孩子库数据、tags 定义随包。
