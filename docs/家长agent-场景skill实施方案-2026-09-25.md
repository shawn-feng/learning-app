## 2. 关键架构决定（含备选与否决理由）

### 2.1 技能正文放哪里

| 方案 | 结论 | 理由 |
|---|---|---|
| **TS 模块常量**（`server/src/agent/skills/parent/*.ts`） | ✅ **已采用** | 跟代码同版本、无打包/资产拷贝问题（`server` 是 esbuild 打包）；**重复规则可以就是同一个常量被两处引用**，物理上不可能漂移 |
| 真 `.md` 文件 + 构建拷贝到 dist | ❌ 否 | 要动构建脚本与打包清单，`asar` 场景易漏；收益（运维直接改文本）目前用不到 |
| 首次运行播种到 `dataDir` | ❌ 否 | 升级时"内置文本更新"与"家长改过的版本"会打架，得再造一套合并/迁移规则 |

### 2.2 为什么不启用 SDK 自带的 Agent Skills（已核实）

内核 0.84.1 确实有 Agent Skills（`SKILL.md` + `<available_skills>` + 渐进披露），但**不用**它，四条理由：

1. 索引里给的是**绝对路径** `<location>`，而我们的 `read` 拒绝绝对路径、`learning-guard` 又把 FS 限制在会话 cwd ⇒ 模型拿到路径也读不到；
2. 服务端默认 `noSkills: true`，打开它等于启用"默认发现目录"：`~/.pi/agent/skills`、`~/.agents/skills`、以及 **cwd 及其所有祖先目录**的 `.pi/skills`——而 cwd 是**模型自己可写**的地方 ⇒ 模型可以给自己写指令（跨天新会话生效），红线级；
3. 我们要的"家长覆盖层"SDK 不提供，反正要自建注册表；
4. server 精确 `0.84.1`、client `^0.84.1`，少依赖一层 SDK 语义就少一处两端分叉。

⇒ **自建索引 + 自建 `load_skill`**，SDK 保持 `noSkills`（现状），**`packages/agent-core` 一行未改**。

### 2.3 三层文本分层（瘦身的安全边界）

| 层 | 内容 | 写在哪 | 例子 |
|---|---|---|---|
| **A 铁律**（永不离开工具描述） | 做错会坏数据/越权的硬约束 | **工具 description + 常驻层 + 场景正文，三处同留**（每条约 1 句） | 改名只走 `parent_rename_course`（不许 upsert）· 课程内容写入是整课替换 · 不可逆先演练复述 · 认证/账户/密码永不触碰 · 同步只到已分配主题 · 家长工作区 ≠ 资料库 |
| **B 场景口径** | 怎么讲、什么顺序、什么不许讲 | **只在场景技能正文** | 考核解读三段式 · "没分析过 ≠ 学得差" · 先核对现有结构再落库 · 复述收尾 |
| **C 细则模板** | 长模板、语法、字段清单 | **技能内靠后的段落** | 报表 markdown 结构 · 互动页 `path` 语法 · 计划重复规则语义表 |

> **执行纪律**：A 层每条一个 ID（A1–A7），测试里逐条核对"三处是否都在"。

### 2.4 装配与加载的数据流（已实现）

```
建会话（ensureEntry，parent / parent-content）
  └─ buildServerParentPrompt(...)                     ← 常驻层
       = 身份 + 红线(A) + 今天 + 库表速查 + 【场景索引 8 行】+ 工作原则
  └─ customTools += load_skill                        ← 唯一新增工具
  └─ toolNames 其余不变                                ← 不切工具集

家长说一句话
  └─ 模型看索引 → 调 load_skill("parent-scene-progress")
       └─ 注册表：内置（TS 常量） ← DB 覆盖（agents.sqlite: ref="skill:<name>"）优先
       └─ 返回正文（首行「已加载场景：中文名（name）」；会话内幂等；64KB 上限截断）
  └─ 正文以**工具结果**追加到消息尾部 ⇒ 前缀缓存不动、会话历史不动、工具面不动
```

**生效时机**：家长会话**长期累积、不做跨天裁决**，systemPrompt 只在**建会话时**读一次。⇒ 部署后**服务端重启**即对所有会话生效（`entries` 是内存表，重启后重建会话，**历史 jsonl 仍在**）。**不需要**强制重置会话。

### 2.5 试点：工具说明下沉 + 场景守卫（2026-09-25 执行，2 把）

**动机（实测）**：工具块才是常驻上下文的大头——45 把 / **25078 字符**（`description` 10585 + 参数 Schema 14493）≈ 常驻提示词（2501）的 **10 倍**。而 Schema 里 **43%（6279）是散文**（属性说明），本就属于 B/C 层。⇒ 说明**下沉到技能**（按需才进上下文），**只留结构**。

| 层 | 放什么 | 为什么不能动 |
|---|---|---|
| 工具 `description` | **一句"干什么" + 自我指路**（`先 load_skill("…")；未加载时拒绝执行`） | 模型**选工具那一刻**手里还没有技能，所以必须留一句 |
| 参数 Schema **结构** | 字段名 / 类型 / 必填 / 嵌套 / 枚举 | **执行前校验与类型转换的依据**（`agent-loop.js:404` → `pi-ai` `validateToolArguments`）；撤了＝关校验（实测空 schema 连 `{随便:1}` 都放行） |
| 参数说明 / 用法 / 铁律 | **场景技能正文** | 技能是"加载后才进上下文"的，正是它该在的地方 |

**场景守卫（`parent-skills.ts`）**：`createParentSkillState()` 建一份**会话级**状态，`load_skill` 与工具**共用**；工具执行前 `scenarioGuard(state, "parent-scene-…")`——本会话没加载过该场景就**拒绝执行**并回可读提示（先 `load_skill`）。**没有它，"按需"只是建议**：说明搬走后模型会靠猜写数据，而结构校验拦不住语义错误。状态不传＝不拦（脚本/测试直调工具仍可用）。

**主动改动一条已拍板决定**：A 层铁律从"**三处同留**"（工具描述 + 常驻层 + 技能）在**下沉工具上**变为"**常驻层 + 技能 + 守卫**"。测试有专门断言守住这条边界（**全量铺开后对所有下沉工具生效**，见 §2.6）。

**试点数字**：这两把 3572 → **1477**（-59%）；39 把业务工具 `description` 9833 → **8895**；**工具块全量 25078 → 22983**；技能正文 11491 → **12705**（+1214 = 下沉的说明）。常驻提示词仍是 2501。

**全量目标（当场估的口径，后已被实测修正）**：`description` 压成一句 + Schema 只留结构，当时估 45 把 **25078 → 10778**；**实测终点是 15997**（差在"通用设施 9 把 / 4843 字符不下沉"），见 §2.6。

### 2.6 A 路线全量铺开（2026-09-25 执行，37 把）

**机制**（`server/src/agent/parent-tool-compact.ts`，只在注册点 `parent-registry.ts` 的 `customTools` 过一道）：

| 机制 | 作用 |
|---|---|
| `firstSentence(desc)` | 取原描述**第一句**作自述（括号内不切句，>140 字截断）⇒ 源码长描述仍是"说明书真源"（不进上下文），**单一真源、不会漂移**，且**幂等**（试点两把由此重新派生，逐字一致） |
| `stripParamDescriptions(schema)` | **原地**删掉 Schema 里所有 `description`；字段名/类型/必填/嵌套/enum/`anyOf` 一字不动（保留 TypeBox 符号与 `prepareArguments`，ISSUE-134 还原层不受影响） |
| `scenesOfTool(name)` | 工具 → 场景，真源＝各技能 `tools` 清单；**多场景任一加载即放行** |
| `compactParentTool(s)` | 描述 → 一句 + 指路（含 `load_skill` 与"拒绝执行"）；`execute` 外包 `scenarioGuard` |
| `COMPACT_EXEMPT_TOOLS` | **不下沉**：`load_skill`、`parent_db_read`/`parent_db_write`/`parent_db_describe`（跨场景通用通道）、`log_activity`（通用设施）；`read/write/edit/ls` 无场景归属 |

**实测（同一套装配 `description + 参数 Schema`）**

| 项 | 原始 | 试点后 | 全量后 |
|---|---|---|---|
| 工具块（45 把） | 25078 | 23086 | **15997（-36%）** |
| `description` | 10585 | 9702 | **6447** |
| 参数 Schema | 14493 | 13384 | **9550**（结构性 7640 是地板） |
| 下沉工具数 | — | 2 | **37** |
| 未归属/豁免 | — | — | **9 把 / 4843** |
| 8 个技能正文 | 11491 | 12705 | **17706**（各技能新增「## 参数速查（本场景工具）」） |
| 常驻提示词 | 4710 | 2501 | **2501（未变）** |

**守卫覆盖全部下沉工具**（含**只读**工具）：说明搬走后，"没加载场景就查询"会变成"误读数据 + 误报给家长"（例如把 `kind=fixed` 考核的"不列课程"当成数据缺失）。**多场景工具**：`parent_list_children`（progress/plan/child）、`parent_read_image` / `parent_read_upload` / `parent_put_material`（course/materials）、`parent_library_topics` / `parent_library_course_content`（progress/course）。

**为什么通用三把不下沉**：它们是跨场景的通用数据通道（P6 退场候选），语义没有单一场景归属；把它们的说明塞进某个技能等于制造错误归属。评估见 `ISSUE-144` §3.3。
