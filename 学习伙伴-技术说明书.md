> **定位**：与《学习伙伴-用户使用说明书》配套，按使用说明书的**功能结构**逐节说明实现方式与数据结构。
> **写法约定**：描述"程序做了什么"——AI 调用了哪个工具、读写哪个库的哪张表哪些字段、调用哪个接口；不展开代码内部。

## 1. 系统总览

### 1.1 三层架构

| 层       | 技术                                | 职责                                          |
| ------- | --------------------------------- | ------------------------------------------- |
| **客户端** | Electron + React（家长/孩子双模式桌面应用）    | 界面、AI 对话、语音评测、本地缓存                          |
| **服务端** | Node + SQLite，REST 接口前缀 `/api/v1` | **所有业务数据的唯一真源**，家庭局域网部署（192.168.1.201:8788） |
| **公网源** | FastAPI + nginx（ECS）              | 仅安装包下载分发与版本登记，与业务数据无关                       |

### 1.2 存储布局（服务端数据目录）

```
<dataDir>/
├── server.sqlite               # 主库：账号/孩子名册/资料索引/会话同步/定时任务/考核结果
├── agents.sqlite                         # 提示词库：AI 提示词的用户自定义版本与历史
├── server-config.json                             # 服务端配置（含 JWT 密钥）
├── kb/<parentId>/<childId>.sqlite             # 孩子库（归属即路径，一个孩子一个文件）
├── parents/<parentId>/parent.sqlite        # 家长库（主题/课程/知识点/题库真源，跨孩子共享）
├── materials/<parentId>/<主题目录>/...         # 学习资料文件（媒体在 media/ 子目录）
├── sessions/<parentId>/<childId>/<file>.jsonl     # 会话记录镜像（与客户端一致，仅追加）
├── logs/server-log.jsonl                          # 服务端访问日志
└── ...                                      # 上传文件、备份 zip 等
```

> 考核出题/判分审计（`exam-audit/<childId>/<YYYYMMDD>.jsonl`）写在**客户端**数据目录，不在服务端。

### 1.3 鉴权与数据隔离

* **家长登录**：邮箱 + 密码 → 签发 JWT 会话令牌（HS256，内容含 `parent_id / email / plan`），后续请求带 `Authorization: Bearer <令牌>`。`parents.cloud_token` 是公网源令牌，不能当会话令牌用。

* **孩子登录**：用孩子档案里存的本地密码哈希校验。

* **归属校验**：每个接口先解析家长身份，再校验目标孩子是否属于该家长（`children.parent_id`）；孩子库文件按 `<parentId>/<childId>` 归属即路径，孩子之间物理隔离。

## 2. 家长端功能实现

### 2.1 登录与许可（对应使用说明 §2.1）

**程序行为**

* 注册 / 登录：`POST /auth/register`、`POST /auth/login`，校验通过后签发会话令牌。

* 许可：`GET /auth/license` 返回许可信息（允许的孩子数、可用功能、订阅有效期）；客户端缓存许可，到期前可离线使用。

* 家长级配置存主库 `settings`，键名带家长前缀（`<parentId>:<键名>`），其中认证类值加密存储；配置变更后主库 `meta` 的 `config_revision` 加 1，客户端据此感知并重新拉取。

**数据结构（主库）**

`parents`

| 字段                      | 说明               |
| ----------------------- | ---------------- |
| id                      | 家长 id（主键）        |
| email                   | 登录邮箱             |
| plan                    | 订阅套餐             |
| cloud_token             | 公网源令牌（**非**会话令牌） |
| license_json            | 许可信息 JSON        |
| created_at / updated_at | 时间戳              |

`settings`

| 字段         | 说明                           |
| ---------- | ---------------------------- |
| key        | 配置键（形如 `<parentId>:<键名>`，主键） |
| value_json | JSON 值（认证类值加密）               |
| updated    | 时间戳                          |

### 2.2 孩子管理（对应使用说明 §2.2）

**程序行为**

* 创建 / 列表 / 修改 / 删除：`POST /children`、`GET /children`、`PATCH /children/:id`、`DELETE /children/:id`（删除同时移除孩子的学习空间）。

* 孩子登录：`POST /children/auth`，用档案里的本地密码哈希校验。

* 创建孩子时即建立其孩子库文件；AI 伙伴的名字与性格并入孩子档案，随提示词生效。

**数据结构（主库）**

`children`

| 字段                      | 说明                                     |
| ----------------------- | -------------------------------------- |
| id                      | 孩子 id（主键）                              |
| parent_id               | 归属家长                                   |
| name                    | 姓名                                     |
| profile_json            | 档案 JSON：年龄/年级/兴趣 + 本地密码哈希 + AI 伙伴名字与性格 |
| created_at / updated_at | 时间戳                                    |

索引：`idx_children_parent(parent_id)`。

### 2.3 主题与课程管理（对应使用说明 §3.3）

**组织原则**：所有知识点按两层分类——顶层是**学习主题**，二层是**课程**；课程是最小的学习与考核单位，课程内部再细分为**知识点**。

**程序行为**

* **五步建主题向导**：家长与 AI 对话完成「意图 → 结构草稿 → 生成内容 → 关联资料 → 确认落库并分配」；落库写入家长库，分配时把课程快照拷入孩子库。

* **双库规则**：家长库是编辑真源（家长端课程管理面板读写它）；孩子库只是分配后的学习副本。给家长面板增改主题/课程，必须写家长库。

* **标签**：主题/课程详情页可直接编辑标签（家长库 `tags` 表 + 课程行的 `tags` 字段）。

* **保存课程**：家长在课程管理面板或通过家长 AI（`parent_course_save` / `parent_topic_save`）保存课程本身——按「主题 + 课程名」为键整行写入家长库 `courses`（排序、状态、本课教学方法、教学文案、考核要点、标签、资料路径等字段一并保存）；主题保存写 `topics`。

* **保存课程的考核内容**：一次提交该课全部「知识点 → 题目」，事务内先清空该课旧挂载再整批写入——题目逐条写入题库 `question_bank`（已存在则整题更新），知识点按「课程 + 名称」查建（`knowledge_points`，名称+详情），挂载关系写入 `course_knowledge_questions`（每项 = 一个知识点 + 挂在其下的若干题）。同一题挂到不同课可关联各自课的知识点。

* **考核方法**：按主题×孩子设置（见下方 `method_spec`），决定抽题时每个知识点抽几题、排除哪些知识点、背诵通过线。

* 相关接口：`GET/POST /assess/*`（知识点、题库、整课内容、考核方法、题目作答记录）。

**数据结构（家长库）**

`topics`（主题）

| 字段            | 说明               |
| ------------- | ---------------- |
| name          | 主题名（主键）          |
| topic_key     | 主题键（英文 key）      |
| method        | 教学方法（教学法真源）      |
| assess_method | 考核方法说明（自由文本）     |
| progress      | 进度摘要             |
| rules_json    | 规则 JSON          |
| method_spec   | 主题级考核方法 JSON（见下） |

`courses`（课程）

| 字段                       | 说明                           |
| ------------------------ | ---------------------------- |
| topic / title            | 所属主题 / 课程名（联合主键）             |
| uuid                     | 课程唯一 id（关系表、计划表、进度视图都用它做真引用） |
| sort_order               | 排序                           |
| status                   | 状态标记（`✅`=已学，默认 `⬜`）          |
| last_review              | 最近学习时间（供主题进度视图汇总）            |
| review_count             | 复习次数                         |
| material / send_material | 学习资料引用 / 已推送资料               |
| tags                     | 标签（逗号分隔）                     |
| lesson_method            | 本课教学方法                       |
| html_path                | 资料相对路径                       |
| teaching_copy            | 教学文案                         |
| assess_rubric            | 每课考核要点（自由文本）                 |

索引：`idx_parent_courses_topic(topic, sort_order)`；`uuid` 上有唯一索引。

`tags`：`tag`（主键）、`dimension`、`criteria`。
`meta`：`key`（主键）、`value`。

视图 `topic_progress`：按主题汇总 `total`（课数）、`learned`（`✅` 数）、`next`（下一个未学课程）、`updated`（最近学习时间）。

`knowledge_points`（知识点 = 每课的考核要点）

| 字段          | 说明                                    |
| ----------- | ------------------------------------- |
| id          | 知识点 id（主键）                            |
| course_uuid | 所属课程                                  |
| name        | 名称（同课内唯一）                             |
| detail      | **知识点详情**（详细描述该知识点教什么、考核期望孩子答到什么；未挂题课程由 AI 按它出题） |
| seq         | 排序                                    |

`course_knowledge_questions`（课程-知识点-题目挂载：课程挂知识点、知识点挂题目）

| 字段                            | 说明                                    |
| ----------------------------- | ------------------------------------- |
| course_id / knowledge_point_id / question_id | 课程 / 知识点 / 题目（联合主键） |
| seq                           | 挂载顺序                                  |
| overview                      | 该知识点在本课的补充说明（可空）                       |

索引：`idx_ckq_course`、`idx_ckq_kp`。一课挂多个知识点，一个知识点多题即例题池（随机抽）。

`question_bank`（题库）

| 字段                      | 说明                                                                    |
| ----------------------- | --------------------------------------------------------------------- |
| id                      | 题目 id（主键）                                                             |
| stem                    | 题干（背诵题=任务描述）                                                          |
| answer                  | 口述题=参考答案要点；**背诵/朗读题=标准原文**                                            |
| scoring                 | 评分标准（口述题用；背诵/朗读题为空）。推荐 JSON（`dims[{dim,points,score,note}]` + `special[]`），写自由文本也可——判分文本拼装与题库展示两处解析均容错回退原文 |
| point_max               | 满分（默认 10）                                                             |
| behavior                | **题级行为**：`speech_recite` 背诵 / `speech_read` 朗读 / `generic` 口述（判题以此为准） |
| note                    | 备注                                                                    |
| knowledge_summary       | 知识点概要（题库浏览展示；未填时自动取关联知识点名称。当前无检索实现，属预留字段）                            |
| options                 | 选择题选项 JSON `[{key,text}]`；`[]`=非选择题                                   |
| created_at / updated_at | 时间戳                                                                   |

> 题目本身不绑定主题/课程，语义由「挂到哪个（课，知识点）」决定，可跨课复用。

**核心 JSON**

`topics.method_spec`（主题级考核方法；require/exclude 键 = **知识点 uuid 或知识点名**，按名引用可一次覆盖多门课的同名知识点）：

```jsonc
{
  "default": {                        // 无孩子覆盖时的回退
    "require": { "<知识点uuid或名称>": 2 }, // 每知识点抽几题；空 = 该课实际挂的知识点各 1 题
    "exclude": ["<知识点uuid或名称>"],
    "rules": { "recitePass": 90 }     // 背诵通过线
  },
  "perChild": {                       // 按孩子覆盖
    "<childId>": { "require": { "…": 3 }, "exclude": ["…"], "rules": { "recitePass": 90 } }
  }
}
```

`question_bank.scoring`（评分标准）：

```jsonc
{ "dims": [ { "dim": "准确性", "score": 6, "points": "要点说明", "note": "补充" } ],
  "special": ["…"] }
```

`question_bank.options`：`[ { "key": "A", "text": "apple" } ]`，`[]` = 非选择题。

### 2.4 学习 / 考核 / 生活计划（对应使用说明 §3.4）

**程序行为**

* **排计划靠 AI 对话**：家长对孩子 AI（或家长助手）说需求，AI 调用计划工具落库——学习计划走 `study_plan_create`（家长）/ `plan_study`（孩子）→ `POST /study-plans`；生活计划走 `parent_plan_create` / `plan_life` → `POST /plans/life`；考核计划走 `exam_schedule_create` / `plan_exam` → `POST /plans/exam` 或排期接口。

* **动态 todolist**：当天待办不落表，`GET /plans/today` 实时聚合三张计划表中「窗口覆盖当天」的行（学习 + 生活合并输出，标注 owner=必须完成项/加分项、是否顺延）。

* **窗口语义**：每条计划有 `start_at`/`due_at` 精确到秒；只给日期时自动补 `00:00:00` / `23:59:59`；匹配按窗口区间而非同日相等。

* **重复规则**：`plan_recurrences` 存每日/每周模板，后台任务每天展开成当天计划行（`last_expanded_date` 游标保证不重复；过 `end_date` 自动停用；仅展开生活/学习，考核不展开）。

* **完成判定（孩子不可手动勾选）**，三条确定性路径，学习与生活都以孩子库 `daily_entries`（每日记录）为依据：

  1. **学习**：每日记录里分类为「学习」、标题**精确等于课程名**的条目，其记录日期落在计划窗口内 → 计划行置 `done`（完成时间记为该记录日）；同时把该条目的 `plan_id` 回填为计划 id、`plan_outcome` 置 `done`（仅当尚未关联时）；
  2. **考核**：孩子提交考核场次 → 考核计划置 `done` 并回填得分（见 §2.5）；
  3. **生活**：定时记录任务（recording）写生活记录时，把对应计划的 `plan_id` 写入该条每日记录（`plan_outcome='done'`）；后台读到「`plan_id` 非空且 `plan_outcome='done'`」的记录 → 对应生活计划置 `done`。

* **到期未完成 → 顺延**：学习/生活计划的过期未完成行判 `missed`，并各复制一条新行到当天（窗口=当天，不继承原窗口）；**考核计划只判 `missed`、不顺延**——考核错过后由家长重排。顺延标记写在 **`origin` 字段**（值 `carry`）；**`carry_from` 字段**记录被顺延原行的 id（溯源）；已取消行不顺延、不计分母。

* **家长修正权**：`POST /plans/status` 支持取消（`cancel`）、撤销判定（`reopen`）、代判完成（`done`）。客户端通道已备好（`planSetStatus`），但当前家长端**没有对应 UI 按钮、AI 也没有对应工具**——属预留能力，尚未接入。

* **创建细节**：

  * `POST /study-plans`：按课程名在家长库反查补全 `topic_key` 与课程 `uuid`；**同日去重不区分制定人**——同课程同模式当天已存在（无论家长还是孩子创建）时，后建方被跳过，即家长建了孩子就不能再建同一条；孩子自建（`creator=child`）自动为选做（加分项）。

  * `POST /plans/life`：家长创建为必做、孩子创建为选做；同 `标题+制定人+日期` 已有待办行则跳过。

  * `POST /plans/exam`：孩子自请考核固定 `creator=child`、`kind=self`，只做「安排」，实际发起与评分走考核页。

**数据结构（孩子库）**——三张计划表字段形态统一：

`study_plans`（学习计划，一课一行）

| 字段                                    | 说明                                                    |
| ------------------------------------- | ----------------------------------------------------- |
| id                                    | 计划 id（主键）                                             |
| parent_id / child_id                  | 归属                                                    |
| topic_key / course_uuid / course_name | 课程真引用 + 展示名                                           |
| mode                                  | `new` 新学 / `review` 复习                                |
| creator                               | `parent`（必须完成项）/ `child`（加分项）                         |
| origin                                | 来源：`conversation` 对话 / `recurrence` 重复展开 / `carry` 顺延 |
| carry_from / recurrence_id            | 溯源：由哪条顺延/规则而来                                         |
| start_at / due_at                     | 窗口                                                    |
| status                                | `pending` / `done` / `missed` / `cancelled`           |
| result / done_at                      | 结果摘要 / 完成时间                                           |
| task_type                             | `required` 必做 / `optional` 选做                         |
| count_in_rate                         | 是否计入完成率分母（默认 1）                                       |

`exam_plan_courses`（考核范围与结果明细）

| 字段                            | 说明                 |

| course_uuid / course_name     | 课程                 |
| knowledge_point_id            | 考点范围（计划期填）         |
| knowledge_point_id            | 考点范围               |
| question_id                   | 开考抽题后回填            |

### 2.5 学习考核管理（对应使用说明 §3.5）

**排考核**

* **固定档**（`kind=fixed`，`daily`/`weekly`）：规则内置——学习计划周期内的「必学」课程全部考核，不走 AI、家长不可改；想自定义范围一律用自定义档。

* **自定义档**（`kind=custom`）：家长通过 AI 助手安排，**必须明确课程名**（一次考核以课程为基本单位，可指定考该课的哪些知识点）；可附带本次考核方法覆盖（`scope.methodSpec`：本次只考某些知识点、通过线等，优先于主题级方法）。

* 排期接口：`POST /exam/schedules`（创建）、`GET /exam/schedules/:childId`（列表）、`POST /exam/schedules/:id/start` / `/:id/complete`（状态流转）、`DELETE /exam/schedules/:id`；固定档阈值读写 `GET/POST /exam/fixed-config`。

**取题（`GET /exam/config/:childId`）**

1. 按排期范围确定课程：自定义档用 `scope.courses`，固定档按周期学习计划取必学课。

2. 每门课按主题级考核方法（含本次覆盖）从题库**结构化直出**，不调用语言模型：按知识点过滤（`exclude` 排除 → `require` 命中；`require` 空 = 该课全部知识点），每知识点随机抽 `require` 数量（缺题跳过，不临时命题）。

3. 每题携带溯源信息 `questionId / knowledgePointId / knowledgePointName`；背诵/朗读题置该课最前（防止原文提前出现），`refText`=题库标准原文、`recitePass`=通过线；选择题下发 `options` 与判分用的 `correctKey`/`answerText`；口述题下发 `scoringText`——**这不是表字段**，是取题时由题库 `answer`（参考答案要点）+ `scoring`（评分标准 JSON）拼装成的判分用文本，只随题下发、不落库。

4. 该课无任何挂载内容 → 按该课**知识点详情**（name + detail，考核要点=知识点）由 AI 出题。

**答题（孩子端）**：顺序作答、切题即锁定、可回看；背诵/朗读题**不显示原文**、可分段录制拼接（切到下一题才锁定）；选择题显示选项列表；问答题语音转写文本可修改。判分所需的锚定信息（评分标准、正确项、通过线）由宿主按送达顺序保管，提交时回填——答题页自身会重排题目编号且丢失未知字段。

**判分**

* **背诵/朗读**：多段录音合并为 16k wav 上传语音评测（见 §4.2），总分 ≥ `recitePass` 判通过；单题评测失败按 0 分计、不阻断整场。

* **选择题**：本地规则判分（孩子说出正确项内容或选项字母 → 满分；命中其它选项 → 0 分；判定不出才交给语言模型兜底）。

* **问答题**：逐题并发交给语言模型，按 `scoringText` 评分。

**落库与回填**

* **总分计算**：孩子端判分后汇总上报——场次总分 = 全部题目每题实得分（`pointGot`）之和（按各题满分的原始分，不是百分比）；另按课程汇总每课答对题数与得分率（单题得分 ≥ 该题满分 60% 记为答对）。

* `POST /exam/attempts`：写入主库 `exam_attempts`（总分 + 逐题明细 `per_question`）、口语题写入 `speech_assessments`、排期置 `done`。

* **后台回填**：把场次结果挂接到孩子库——
  * `exam_plans.score` **不重算**，直接回填该场次的 `exam_attempts.score` 快照，同时置 `status='done'`、`attempt_id`、`done_at`；若该场次没有对应计划行（如孩子未排期直接开考），自动新建一条考核计划（来源 `conversation`、类型 `custom`、状态 `done`）；
  * `exam_plan_courses`：先清空该计划旧明细，再按 `per_question` 整批回填（课程、知识点、题目 id、每题得分与满分），重复执行不产生重复行。

* **审计**：客户端把考核各环节事件追加写入 `exam-audit/<childId>/<日期>.jsonl`，每行含时间与环节名——`select`（本次从题库抽了哪些题）、`generate`（AI 出题路径的题目内容）、`score`（每题判分依据与结果）。结构化直出的场次没有 `generate`/`select` 事件，可据此区分出题路径。

**记录与掌握度**

* 考核记录：`GET /exam/attempts/:childId`（逐场逐题）、`GET /exam/course-records/:childId`（按课程）、`GET /assess/questions/:questionId/records`（按题）。

* 课程进度：`GET /courses/status/:childId` 读孩子库视图 `course_progress`。

### 2.6 积分奖励体系（对应使用说明 §3.6）

**程序行为**

* **分档配置**：家长按比例区间配置档位（待办完成率档、考核得分率档，档数不限）；保存时校验区间升序、连续覆盖 0~100%、互不重叠、100% 为独立档。接口：`GET/PUT /rewards/:childId/config`。

* **每日两组各算一个比例**：

  * **待办完成率**：分母 = 当天窗口覆盖、计入完成率（`count_in_rate=1`）且非选做的计划行（无论完成与否）；分子 = 已完成数。学习 + 生活两表合并。考核计划不进此口径。

  * **考核得分率**：当天已完成的考核场次 Σ得分 / Σ满分（多场次加权合并）；当天无已完成考核则该组不结算。

* **门控**：加分项（孩子自定计划）要加分，须家长组同口径达标——待办完成率 ≥ 配置阈值（默认 100%）、考核得分率 ≥ 配置阈值（默认 90%）。

* **评档发分**：按档位区间给分（左闭右开，100% 为闭区间档）；加分项命中负分档强制 0（永不扣分）；门控未开也强制 0。

* **结算时机**：后台调度每 2 分钟一轮——**当天只写实时统计，档位结算与流水写入针对「上一日」**（其窗口已确定结束，分母口径稳定）。结算为一次性语义：结算后回改昨日计划不会重发/追回流水，纠错走手工调整。

* **幂等**：流水表上（孩子+归属日+类型+来源表+来源id）唯一索引，重复结算不会重复发分。

* **余额**：真源是流水净额，`points_balance` 只是每次结算后重算的缓存。

* **兑换**：孩子端提交 → 事务内校验余额 → 写兑换申请（`pending`）+ 扣分流水 → 家长在家长端履约（`fulfilled`）或拒绝（`rejected`）。接口：`GET /rewards/:childId`（余额 + 当日统计 + 流水 + 近 N 天趋势）、`POST /rewards/:childId/redeem`。

### 2.9 学习资料库与 PiBridge（对应使用说明 §3.9）

**程序行为**

* **资料组织**：资料文件按 `<parentId>/<主题目录>/` 存放（媒体在 `media/` 子目录）；索引存主库 `materials`。

* **索引用途**：`materials` 表是「资料 id → 相对路径」的**解析真源**——内容下发、列表、删除都查它而不扫磁盘（资料文件量大，扫盘不可行）。资料 id = 相对路径的 base64url 编码，主键含家长 id，跨家长同路径互不冲突。客户端加载资料/媒体时按 id 经内容接口取文件。

* **上传与登记**：`POST /materials/upload` 传文件、`POST /materials/index` 登记索引、`GET /materials/list` 列表、`GET /materials/content/:id` 取内容（**只查索引表不扫磁盘**，新资料必须先登记否则取不到）、`DELETE /materials/:id` 删除。

* **家长上传辅助**：`parent_upload_material` 上传、`parent_transcribe_media` 音视频转写、`parent_read_image` 图片识读。

* **客户端加载**：HTML 资料以真实 URL 顶层加载——客户端在协议层完成「拉取原文 → 适配改写 → 注入 PiBridge 脚本与字号设置」后返回；音视频/图片经 `asset://`/`media://` 代理到内容接口；无服务端文件的旧内嵌资料回退 dataURL 方式。

* **PiBridge 通讯协议**（资料页 ↔ 宿主唯一标准）：

  * 安全前提：资料页运行在 sandbox 不透明源 iframe 内，只经 `postMessage` 通讯；宿主校验消息来源与类型白名单；只传语义数据，无任意代码执行。

  * 采集模式：默认 `auto`（自动采集点击/滚动/输入/提交/查词）；页面声明 `<meta name="pi-bridge" content="capture=manual">` 时只上报显式事件。

  * 作者 API（唯一入口 `window.PiBridge`）：`emit(动作,数据)` 上报事件；`request(动作,数据)` 调宿主能力（Promise 回执，12 秒超时）；`on/off` 接收宿主命令。

  * 可靠性：页面就绪前不下发命令、请求 id 配对、超时、iframe 重建自动作废在途请求。

  * **动作目录**（区分实现状态）：

    * 已实现的宿主能力：`tts.speak`（宿主逐句串行朗读）、`lookup`（查词气泡）。

### 2.10 系统设置（对应使用说明 §3.10）

## 3. 孩子端功能实现

### 3.1 进入学习与学习主界面（对应使用说明 §4.1 / §4.2）

* 孩子选择自己的头像、输入本地密码（`POST /children/auth`）进入学习模式；数据读写全部落**自己的孩子库**。

* 主界面 = 左侧内容面板（学习资料/待办）+ 右侧对话区；孩子的 AI 伙伴用孩子版提示词（身份 + 行为规范），会话按孩子隔离、跨重启恢复最近会话。

* 孩子侧通用工具：`display_content`（生成学习内容面板）、`get_date`、`get_progress`（读课程进度）、`kb_query` / `kb_insert` / `kb_update`（读写自己库的每日记录/课程/标签）、`create_html_lesson`（生成网页资料）、`child_self_info`（读自己档案）、`page_action` / `page_inspect`（感知与操作资料页）。

### 3.2 课程学习（对应使用说明 §4.3）

* 点读 / 查词：资料页内取词触发 `lookup`，宿主弹查词气泡并朗读；页内 TTS 走 `tts.speak` 队列。

* **学习完成信号**：孩子的学习过程会以「学习」分类、课程名为标题写入每日记录（孩子库 `daily_entries`）；后台统计发现某条记录的日期落在某条学习计划的窗口内（标题与课程名精确一致），即把该计划行置 `done` 并把该记录关联到计划（`plan_id` / `plan_outcome='done'`）——孩子全程无需勾选。

* AI 可用 `display_content` 主动把课件/练习推到内容面板，新内容自动弹开且跨重启保留。

### 3.3 英语场景课（对应使用说明 §4.4）

**程序行为**

* 场景资料 = 带角色扮演的场景网页（页面声明 `<meta name="pi-scenario">`）；进入场景课后启用**独立的场景 AI 会话**（会话键 = `孩子|scene|课程`），工具白名单只有 `scene_command`。

* AI 用 `scene_command` 驱动演出，指令 6 种（无结束类指令——任务达成靠对话收束）：

| 指令          | 作用                                                                   |
| ----------- | -------------------------------------------------------------------- |
| `say`       | 角色说话（英文台词 + 中文对照，宿主自动朗读并显示字幕）                                        |
| `move`      | 角色移动（舞台横坐标 10~1120，或目标名：window/sofa/table/plant/lamp/tv/picture/rug） |
| `act`       | 角色做动作（turn-on-lamp / open-window / sit-sofa / jump / dance 等）        |
| `show`      | 让隐藏角色登场                                                              |
| `highlight` | 高亮某物品或角色                                                             |
| `update`    | 更新任务进度（task/progress/total）                                          |

* 指令经宿主白名单校验后以 `scene.<指令>` 下发给场景页；宿主还会推送状态类消息：`scene.busy`（AI 思考中）、`scene.mic.status` / `scene.mic.result`（语音球状态）。

* **语音球交互**：页面只上报 `scene.mic.press` / `scene.mic.release`（沙箱 iframe 内无麦克风权限）；宿主负责录音 → 语音识别 → 把文本连同录音交场景会话 → 结果经 `scene.mic.result` 回给页面。

* 页面上行事件：`scene.ready`（场景就绪，宿主通知对话区进入场景模式）、`scene.item-click`（孩子点物品/角色）。

### 3.4 学习考核（对应使用说明 §4.5）

* **今天可参加**：孩子端读取自己的待考排期（`pending` 状态），进入后按 §2.5 的取题流程下发题目；历史场次在考核记录里回看。

* 作答与判分规则见 §2.5（背诵可分段录制拼接、切题锁定；选择题本地判分；问答题转写可改）。

* 提交后：主库写场次结果与口语存档，排期与孩子库考核计划同步置 `done`，考核计划明细回填每题得分。

### 3.5 我的积分（对应使用说明 §4.6）

* 孩子端 `GET /rewards/:childId` 查看余额、当日两组统计（含门控是否解锁）、流水与近 N 天趋势。

* **应用内兑换**：目录内虚拟权益（应用内/视频/游戏/装扮）提交后即时扣分生效；**现实奖励**（`kind=parent`）提交后生成 `pending` 申请，等家长在家长端履约。

* 流水每行可看到原因（命中档位、比例、门控状态）。

### 3.6 孩子端设置（对应使用说明 §4.7）

* 模型切换：家长设默认，孩子可改选。

* 自建提醒：AI 调用 `schedule_task` 工具创建 `reminder` 类定时任务（owner=`child`），到点语音播报。

* 定时记录：由后台按孩子配置自动运行（见 §4.1），孩子无感。

## 4. 通用后台机制

### 4.1 后台调度与自动判定（服务端 worker）

* 服务端进程内置调度器，**每 2 分钟**一轮，顺序执行（保证依赖顺序），启动时另有一次补跑：

  1. **重复规则展开**：把 `plan_recurrences` 中命中当天的规则展开成计划行（游标幂等）。

  2. **信号判定**：学习域按每日记录判定（分类「学习」、标题与课程名精确一致、记录日期落计划窗口）→ 计划置 `done`；生活域按每日记录中带计划 id 且结果为完成的证据判定；随后把已提交的考核场次回填到考核计划与明细。

  3. **到期处理**：学习/生活计划的过期未完成行判 `missed` 并复制顺延行到当天；考核计划只判 `missed`（错过后由家长重排，不顺延）。

  4. **统计与积分结算**：写当日 `reward_daily_stats`（实时进度）；并结算「上一日」——评档、写流水、重算余额（幂等）。

  5. **定时任务执行**：按 `scheduler_tasks` 触发 recording / 自动新会话 / 提醒（提醒类按 5 分钟桶匹配落点，避免错过）。

* 触发配置以服务端为准（任务表 + 分配），不依赖客户端在线；所有写入均幂等（流水唯一索引、展开游标、统计 upsert），重复执行不产生副作用。

### 4.2 语音评测

* **评测在客户端主进程本地进行**，不经业务服务端；两家引擎并存，设置页可切换默认。

* **腾讯云智聆**：中文用 `16k_zh`（自动在长文本时降级段落模式规避字数限制），其余用 `16k_en`。限制：句子模式中文 ≤30 字 / 英文 ≤60 词；段落模式中文 ≤120 字 / 英文 ≤300 词；超段落上限需拆句多次评测。

* **声希**：客户端直连鉴权取得临时凭证（约 120 分钟有效）后评测；中文（背诵/段落）`cn.pred.score`、英文 `en.sent.score`；**无字数硬上限**，但录音时长须与文本大致匹配，对齐不足会评测超时失败。

* 题型自动选引擎与评测维度；结果统一映射为存档结构写入主库 `speech_assessments`。

`speech_assessments`

| 字段                                      | 说明           |
| --------------------------------------- | ------------ |
| id                                      | 记录 id（主键）    |
| parent_id / child_id                    | 归属           |
| topic_key / course_name / question_type | 上下文          |
| ref_text                                | 参考文本         |
| audio_file_id                           | 录音文件         |
| overall / pron                          | 总分 / 发音分     |
| dimensions_json / detail_json           | 维度分 / 明细     |
| is_exam / exam_attempt_id               | 是否考核内 / 关联场次 |
| created_at                              | 时间戳          |

索引：`idx_speech_child(child_id, created_at)`。

## 附录 D：已知注意点

1. **积分结算为一次性语义**：档位结算针对「上一日」且幂等（流水唯一索引）——结算后回改昨日计划不会重发/追回流水，纠错需手工调整（改流水 + 重算余额）。

2. **完成率分母口径**：代码按「当天窗口覆盖的全部计入行（含尚未到期的未完成行）」作分母，与早期设计稿"未到期不进分母"的写法不一致，以代码口径为准。

3. **`settings` 键名前缀**：家长级配置的键带 `<parentId>:` 前缀，按孩子读取时需拼接。

4. **背诵题原文必须逐字权威**：`refText` 来自题库标准原文，不可由 AI 现写。

5. **答题页题目编号会重排且丢失未知字段**：判分锚定信息（评分标准/正确项/通过线）必须由宿主按送达顺序保管、提交时回填。

6. **资料内容接口只查索引**：新上传资料必须先登记索引，否则取不到。

7. **视频必须 H.264 编码**（禁 H.265/HEVC），否则 Linux 端无法解码。

8. **声希评测失败模式**：表现为评测超时，根因通常是录音与参考文本对齐不足（时长不匹配），与字数无关。

> 本文与《学习伙伴-用户使用说明书》章节一一对应；数据结构以服务端实际建表为准，如与设计稿冲突以代码与 `ARCHITECTURE.md` / `EXAM-ARCHITECTURE.md` 为准。
